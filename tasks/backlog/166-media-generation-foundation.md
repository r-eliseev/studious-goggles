# Генерация не только картинок: общая основа для аудио и видео

## Описание
Решение владельца 2026-10-31: генерация музыки, звуков и видео — задачи на следующие версии (раньше видео и аудио были вне объёма: `docs/product.md`, «Не входит»; `docs/specs/image-client.md`, «Вне объёма»).

Подготовительная задача для 167 (музыка), 168 (звуки) и 169 (видео): исследовать и спроектировать, как ядро, хранилище и интерфейс работают с результатом другого вида, чтобы три задачи не переделывали одно и то же по отдельности.

Зависит от: —
Среда: Linux или Windows.

## Критерии готовности
- Исследование: какие встроенные провайдеры (fal, OpenRouter, Together) и какие модели дают музыку, звуковые эффекты и видео, через какой API (очередь, синхронный ответ, ссылка на файл), параметры (длительность, формат, разрешение, fps), форматы результата, размеры файлов, цены и единицы цены. Только по документации и проверяемым источникам с датой; неизвестное помечено «неизвестно».
- ADR: обобщение «генерации» на вид результата (картинка, аудио, видео) — домен, контракт провайдера (ADR 0003), хранение файлов и лимиты размера (ADR 0022), каталог моделей, ассистент (инструмент или инструменты), карточка результата.
- Решение о воспроизведении аудио/видео в обеих оболочках (MAUI и Avalonia): компоненты и пакеты с лицензией, поддерживаемые платформы; новый пакет — только с ADR.
- План разбит на этапы; задачи 167–169 получают зависимость от готовых этапов.

## Анализ
Предварительно, по коду на `b4d00d9` (уточнить при исследовании):
- Ядро и хранилище рассчитаны только на картинки: `ImageModel`, `IQueuedImageProvider`, `ImageGenerationRequest/Result`, `IImageFileStore`, `FileImageStore` (расширения только для `image/png`, `jpeg`, `webp`), `BoundedBase64ImageDecoder` и лимит `ProviderResponseLimits.Image` 50 МиБ (видео может быть больше), инструмент ассистента `generate_images`.
- Ссылки провайдеров на файлы истекают (`docs/architecture.md`, «Ограничения») — результат нужно скачивать сразу; для больших файлов — потоковая запись без загрузки целиком в память.
- Интерфейс: карточка генерации показывает картинку; для аудио/видео нужны плеер, длительность, обложка/кадр. В MAUI есть `CommunityToolkit.Maui.MediaElement` (отдельный пакет), в Avalonia встроенного плеера нет — варианты исследовать.
- Журнал расходов (021) и отмена (024) должны работать для любого вида результата.

## План
Исследование и ADR выполнены при планировании 2026-11-06 (claude-audit), этапы — отдельными задачами 199–209.

## Отчёт
Исследование — `docs/knowledge/media-generation.md` (OpenRouter видео и аудио, fal и Together для справки, MediaElement и LibVLCSharp; все источники с датой 2026-11-06, непроверенное помечено). Решение — ADR 0027 (вид результата `MediaKind`, потоковое хранение и лимиты, видео через очередь заданий, каталог `video_models` и цена по `pricing_skus`, настройки сессии и инструмент `generate_video`, MediaElement в MAUI, LibVLC в Avalonia после пробника, расходы `Video`/`Music`).

Решения владельца 2026-11-06: всё через OpenRouter; в Avalonia — LibVLC сразу.

Этапы: 199 (домен и хранилище), 200 (каталог видео и цена), 201 (задания OpenRouter), 202 (GenerationService: запуск, ожидание, восстановление), 209 (отмена и действия), 203 (настройки сессии, инструмент ассистента, оценка), 204 (интерфейс без плеера), 205 (MAUI MediaElement), 206 (пробник LibVLC на Avalonia 12), 207 (плеер Avalonia), 208 (живая проверка Lyria для музыки). Звуковые эффекты (168) — нет моделей на OpenRouter.

Живыми запросами ничего не проверялось: только публичные каталоги без ключа (`/api/v1/videos/models`, `/api/v1/models`, `api.fal.ai/v1/models`) и документация.
