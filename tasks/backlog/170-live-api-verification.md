# Проверка живых API провайдеров с ключами владельца

## Описание
Многие формы запросов и ответов проверены только на заглушках HTTP (`docs/status.md`, «Открытые вопросы»). Ручная проверка с настоящими ключами владельца закрывает эти вопросы или превращает расхождения в задачи. Агент ключей не получает: прогон делает владелец, агент готовит сценарий и разбирает результат по отладочному трейсу (`docs/specs/debug-trace.md`), из которого ключи и поля аккаунта уже вырезаны.

Зависит от: — (удобнее после 163/165, чтобы ставить APK поверх; можно и на Avalonia-десктопе).
Среда: реализация инструмента — Linux или Windows; запуск с ключами — владелец; разбор отчёта — агент.

## Критерии готовности
- По каждому пункту сценария записан результат «совпадает с заглушкой / расходится (как) / не проверено (почему)» с датой, моделью и версией приложения.
- Для каждого расхождения заведена задача с фрагментом трейса без ключей и личных данных; подтверждённые факты перенесены в `docs/knowledge/` и ADR (0009, 0011, 0012, 0013, 0017, 0023), открытые вопросы в `docs/status.md` закрыты или уточнены.
- Потрачено не больше бюджета, который владелец назовёт перед прогоном.

## Анализ
Непроверенное на живом API (по `docs/status.md` на `040c198`):
- OpenRouter: параметры `aspect_ratio`, `resolution` (единица 512/768), `output_format`, `quality` (020, ADR 0011); `input_references` (018, ADR 0012); ответ модели с картинкой на входе и цена описания (019, ADR 0013); тарифицируются ли неудачные chat completions.
- fal: цена моделей (`GET /v1/models/pricing` без ключа — 401, форма ответа неизвестна, 093).
- Together: живой ответ `images/generations` с `response_format=base64`, списание, 422 при фильтрации (ADR 0017, 0023).
- OpenAI-совместимые `images/generations` и чат, Anthropic Messages `anthropic-version: 2023-06-01`, `GET /models` (036, ADR 0009); `chatModels` из 156 на живом провайдере.

## План
Решение владельца 2026-10-31: проверка — **скрипт, который получает ключи параметрами**; бюджет — **около 1 $ на провайдера**, это десятки запросов. Сначала падающий тест, затем код (ub-mode).

1. **Инструмент.** Консольный проект `ImageGen/ImageGen.LiveCheck` (net10.0, ссылки Core и Data, в `ImageGen.slnx`), чтобы проверять настоящие клиенты приложения (`OpenRouterClient`, `FalImageProvider`, `OpenAiCompatibleClient`, `AnthropicCompatibleClient`), а не отдельный curl. Запуск: `dotnet run --project ImageGen/ImageGen.LiveCheck -- --openrouter-key <k> --fal-key <k> --together-key <k> [--openai-compatible <providers.json>] [--budget-usd 1] [--only openrouter,fal] [--out tmp/live-check]`. Провайдер без ключа пропускается с пометкой «не проверено».
2. **Ключи.** Только в памяти процесса (`ISecretStore` в памяти). В вывод, отчёт и трейс не попадают: трейс пишется через `FileDebugTrace` с теми же правилами вырезания заголовков и полей аккаунта, плюс отдельная проверка отчёта на отсутствие ключа перед записью. В справке — предупреждение, что параметры командной строки видны в истории оболочки; поддержать также переменные `IMAGEGEN_LIVE_<PROVIDER>_KEY` как альтернативу.
3. **Бюджет.** На провайдера — лимит в долларах (по умолчанию 1 $) и лимит запросов (по умолчанию 40). Учитывается известная цена (`usage.cost` OpenRouter); для провайдеров без цены в ответе (fal, Together) — оценка по таблице цен из `docs/knowledge/providers.md` и каталогов на дату запуска, в отчёте помечается «оценка». Перед каждым платным запросом — проверка, что остаток покрывает его оценку; иначе сценарий провайдера останавливается. Самые дешёвые модели и минимальные размеры; одна картинка на запрос.
4. **Сценарии** (по пунктам «Анализа»): OpenRouter — каталог моделей и цены, генерация с каждым параметром `aspect_ratio`/`resolution`(512, 768, 1K)/`output_format`/`quality` по одному запросу, генерация с `input_references` (1 и 2 картинки), описание картинки (019), чат с инструментом `generate_images`, неудачный чат-запрос (проверка, списано ли); fal — submit/poll/result одной дешёвой модели, `GET /v1/models/pricing` с ключом (форма ответа); Together — `images/generations` с `response_format=base64` и `output_format` png/jpeg, промпт, на котором ожидается фильтрация (проверка 422); OpenAI-/Anthropic-совместимый — по переданному `providers.json`, если есть.
5. **Отчёт.** `tmp/live-check/<дата>/report.md`: по каждому пункту — ожидание, факт, «совпадает / расходится / не проверено», модель, цена (факт/оценка), ссылка на запись трейса; итог по бюджету. Владелец присылает отчёт и трейс; агент переносит факты в `docs/knowledge/`, ADR и `docs/status.md` и заводит задачи на расхождения.
6. **Тесты** (без сети, `StubHttpMessageHandler`): разбор аргументов и переменных; остановка по бюджету и по числу запросов; пропуск провайдера без ключа; ключ не попадает в отчёт и трейс; сценарий с расхождением даёт статус «расходится».
7. Документы: `docs/knowledge/dev-environment.md` (как запустить проверку), `docs/architecture.md` (новый проект). Проверки: тесты LiveCheck, `dotnet format`, `scripts/check.sh`; сам прогон с ключами — владелец.

Файлы: `ImageGen/ImageGen.LiveCheck/ImageGen.LiveCheck.csproj`, `Program.cs`, `LiveCheckOptions.cs`, `BudgetGuard.cs`, `InMemorySecretStore.cs`, `Scenarios/*.cs`, `Report/*.cs` (новые); `ImageGen/ImageGen.LiveCheck.Tests/*` (новые); `ImageGen/ImageGen.slnx`; `docs/knowledge/dev-environment.md`; `docs/architecture.md`; эта задача (отчёт).

## Отчёт

Инструмент `ImageGen.LiveCheck` и тесты подготовлены. Добавлен запуск с ключами из аргументов или переменных `IMAGEGEN_LIVE_*_KEY`, ограничение бюджета/числа запросов, выбор моделей, сценарии OpenRouter/fal/Together и конфигурируемых OpenAI-compatible/Anthropic клиентов. Отчёт и безопасный HTTP trace записываются в каталог `--out`; все клиенты приложения создаются через `AddImageGenCore` и `LoggingHttpHandler`. Описания запуска добавлены в `docs/knowledge/dev-environment.md`, структура — в `docs/architecture.md`.

Проверено: `dotnet build ImageGen/ImageGen.LiveCheck/ImageGen.LiveCheck.csproj --no-restore`; `dotnet test --project ImageGen/ImageGen.LiveCheck.Tests/ImageGen.LiveCheck.Tests.csproj --no-restore` (4/4); `dotnet format` обоих новых проектов (`--verify-no-changes --no-restore`); CLI отклоняет нулевой бюджет без вывода значения ключа. Живые API и оплата не проверялись: для этого необходим запуск владельцем с ключами и выбранным бюджетом. Результаты сценариев пока помечены как требующие сверки с trace и заглушками; факты для ADR/knowledge и задачи по расхождениям будут оформлены после получения live-отчёта. Сценарий неудачного chat completion реализован обычным коротким запросом: намеренно отправлять гарантированно невалидный/платный запрос нельзя считать безопасным до согласования конкретного провайдера и модели.

### 2026-11-01, claude-audit — ревью перед прогоном
До прогона с ключами: сценарии `input_references` (`LiveCheckRunner.cs:121`) и «image description» (`LiveCheckRunner.cs:130`) отправляют `data:image/png;base64,AQID` — это 3 байта (`01 02 03`), а не изображение. Провайдер отклонит запрос или обработает мусор, и открытые вопросы 018 (форма `input_references`) и 019 (описание картинки) прогон не закроет, но бюджет потратит. Нужен настоящий PNG: результат первой успешной генерации этого же прогона (предпочтительно — реальный кадр), либо встроенный маленький валидный PNG (например, 8×8) как запасной. Тест: в теле запроса этих сценариев — декодируемый PNG (сигнатура `89 50 4E 47`). Решение владельца 2026-11-01 — исправить до прогона.

### 2026-11-01, claude-audit — ревью PR #62, бюджет
Бюджет на деле ограничен только числом запросов. `LiveCheckRunner.FindEstimatedImageCost` (`LiveCheckRunner.cs:333`) берёт `Prices.Min` по всем записям цены модели, а единицы у них разные (`Image`, `Megapixel`, `Token`, `Request`). Если модель тарифицируется по токенам, минимум получается порядка $0.00000x, и `BudgetGuard.TryReserve` (`BudgetGuard.cs:13`) пропускает всё до потолка в 40 запросов. Фактический `CostUsd` из ответа попадает в отчёт, но в `BudgetGuard` не вычитается, хотя пункт 3 плана требует учитывать известную цену. При `--model` с дорогой моделью лимит в 1 $ можно превысить. Предлагается: оценку брать только по единицам `Image`/`Request` (или `Megapixel` × размер запроса), а если подходящей нет — по запасной оценке; после ответа сверять резерв с фактическим `CostUsd`. Тесты: модель только с токенной ценой → оценка не меньше запасной; фактическая цена выше оценки → следующий запрос не проходит по бюджету. Исправить до прогона вместе с заглушкой PNG.
