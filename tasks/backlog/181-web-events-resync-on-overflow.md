# Web: при переполнении очереди сразу отправлять resync

## Описание
Находка код-ревью 2026-11-02 (PR #67). `ImageGen/ImageGen.Web/Events/EventHub.cs`, `Publish`: если канал подписчика полон, очередь очищается, текущее событие теряется и ставится флаг `NeedsResync`. Сам `resync` пишется только при следующем `Publish`. Если событий больше нет, клиент не узнаёт, что пропустил данные (например, последнюю генерацию прогона), и показывает старое состояние.

Зависит от: 179 (тот же каталог `Events/`; делать после её слияния, чтобы не конфликтовать в `EventApiTests.cs`).
Среда: Linux или Windows.

## Критерии готовности
- При переполнении в очищенный канал сразу пишется `resync`, без ожидания следующего события.
- Текущее событие после `resync` тоже пишется (порядок: `resync`, затем это событие).
- Флаг `NeedsResync` и его ветка удалены (после очистки канал пуст, запись не может не пройти).
- Существующий тест `FullSubscriberQueue_IsReplacedWithResyncMarker` зелёный; новый тест проверяет сценарий без следующего события.

## Анализ
Канал создан с `Capacity = 256`, `FullMode = Wait`; `TryWrite` при полном канале возвращает `false`. Публикация для подписчика идёт под `lock (subscriber)`, поэтому между очисткой и записью другой писатель не вмешается.

## План
1. Падающий тест в `EventApiTests`: `FullSubscriberQueue_SendsResyncWithoutFurtherEvents`. Подписаться через `hub.Subscribe()`, вызвать `NotifySessionChange` ровно 257 раз (256 заполняют канал, 257-е переполняет). Больше событий не публиковать. Ожидать: первое прочитанное — `resync` с `{}`, второе — `session` с id 257-го вызова; затем `Reader.TryRead` возвращает `false`.
2. Фикс в `Publish`, внутри `lock (subscriber)`: если `TryWrite(event)` не прошёл — очистить канал (как сейчас), `TryWrite(resync)`, затем `TryWrite(event)`. Ветку «`if (subscriber.NeedsResync)` в начале» и свойство `Subscriber.NeedsResync` удалить.
3. Проверить существующий тест с 258 событиями: при новом порядке после 257-го канал = [resync, session257], 258-е добавится — первые два прочитанных `resync`, `session`, тест остаётся верным.

Файлы: `ImageGen/ImageGen.Web/Events/EventHub.cs`, `ImageGen/ImageGen.Web.Tests/EventApiTests.cs`.
