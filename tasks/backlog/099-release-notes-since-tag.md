# Заметки о релизе: что изменилось с прошлого тега

## Описание
Замечание по релизу v0.1.4 (2026-10-29): в описании релиза на GitHub стоит «Релиз v0.1» и перечислены только задачи 001–015 и 034; работа последних недель (Avalonia, хранилище, сессии и прочее, задачи из `tasks/backlog` и `tasks/DONE.md`) не видна. Все релизы v0.1.x получают одинаковый текст.

Что известно: `.github/workflows/release.yml` (шаг «Release notes») берёт папку релиза из тега без патч-номера (v0.1.4 → `tasks/v0.1`) и вызывает `scripts/release-notes.sh`; скрипт перечисляет только задачи `done` с релизом `v0.1` (в папке и в `tasks/DONE.md`). Задачи из `backlog`, сделанные между тегами, в заметки не попадают. Как определять «что вошло» (задачи, чьи файлы или коммиты изменились между предыдущим тегом и текущим, коммиты с префиксом `NNN-`, слияния PR), решить в «Анализе».

Правка `scripts/` и `.github/workflows/` — по явной просьбе владельца (эта задача и есть просьба, если план одобрен).

Зависит от: —
Среда: Linux или Windows.

## Критерии готовности
- Заметки о релизе vX.Y.Z перечисляют задачи, завершённые между предыдущим тегом и этим (номер и заголовок), независимо от папки задачи; заголовок — версия тега.
- Для первого тега (предыдущего нет) — все завершённые задачи.
- Скрипт можно запустить локально на двух тегах и получить тот же текст; способ описан в `docs/` (где описан релиз).
- `scripts/check.sh` проходит.
