# Поиск по смыслу: исследование и ADR (тексты и картинки)

## Описание
Решения владельца (2026-10-28): после нечёткого поиска (079) — поиск по смыслу по эмбеддингам, и по текстам (названия, промпты, описания), и по самим картинкам («найди все картинки с маяком» без слова в промпте). Чем считать векторы — решить после исследования. Эта задача — только исследование, пробный код и ADR на утверждение владельцу; реализация — новые задачи по итогам.

Зависит от: 079 (тот же интерфейс поиска в ядре; можно начинать исследование параллельно).
Среда: любая (документ и пробный код в `poc/`); пробный код ONNX — на Linux.

## Критерии готовности
- `docs/log/` или раздел задачи: сравнение минимум трёх вариантов по таблице: где считаются векторы (API провайдера — например эмбеддинги OpenRouter или другого BYOK-провайдера; локальная модель ONNX — текстовая и мультимодальная типа CLIP/SigLIP), качество на английском и русском, цена, размер в сборке, работа на Android/iOS, приватность (что уходит провайдеру), лицензия модели.
- Для картинок: можно ли общим пространством векторов (мультимодальная модель) искать картинки текстом; если нет — вариант «через описание картинки» (Img2Text, 019) и его цена.
- Пробный код в `poc/backlog/081-semantic-search-research/`: замер скорости и размера для лучшего локального варианта на Linux.
- Хранение векторов: SQLite (таблица с BLOB и перебор в памяти) или расширение (`sqlite-vec`) — оценка для тысяч и десятков тысяч картинок.
- ADR `docs/decisions/NNNN-semantic-search.md` со статусом «предложено» и вопросами владельцу; после ответа — задачи на реализацию (`scripts/new-task.sh --publish backlog …`).

## Анализ
- Принцип продукта: BYOK, приложение не стоит между пользователем и провайдером по деньгам; приватность — промпты и картинки уходят только провайдерам, которых выбрал пользователь (F10.6). Отправка картинок на эмбеддинги — новый поток данных, нужно согласие (как F10.6).
- Новые пакеты (например, `Microsoft.ML.OnnxRuntime`) — только с ADR (`docs/conventions.md`, «Зависимости»).
- Факты о моделях и API проверять по первоисточникам и записывать с датой; неизвестное — «неизвестно» (AGENTS.md).

## Отчёт

Исследование выполнено (`claude-536f`, 2026-10-29). Результат — ADR 0016 (статус «предложено»), пробный код с замерами в `poc/backlog/081-semantic-search-research/`. Реализация не начата: задачи на реализацию заводятся после ответов владельца на вопросы ниже.

**Что сделано**
- Варианты сравнены по таблице из критериев: провайдер (OpenRouter), мультимодальный провайдер, локальные ONNX-модели, описание картинки (019). Факты взяты из каталога OpenRouter (38 моделей эмбеддингов, 7 принимают картинки), из схемы `POST /embeddings` в `openapi.json` и из карточек моделей Hugging Face (лицензии, файлы ONNX, размеры). Все цены и даты — на 2026-10-29.
- Пробный код `SpeedProbe` (.NET 10, ONNX Runtime 1.31.1): размер файла, время одного прохода для текста (e5-small 10 мс, многоязычный CLIP-текст 13 мс) и картинки (CLIP B/32 37 мс), перебор векторов в памяти (10 000 — 8 мс, 50 000 — 8–13 мс на запрос). Замеры на облачном Linux-CPU, не на телефоне.
- Хранение: SQLite с BLOB и перебор в памяти — рекомендуется; `sqlite-vec` в NuGet только alpha (`0.1.7-alpha.2`), не принят.
- Рекомендация: текст — через OpenRouter (`baai/bge-m3`, $0.01 за 1 млн токенов); картинки — после согласия владельца на отправку картинок провайдеру; до согласия — поиск по описаниям картинок (019). Локальные модели (≈860 МБ) — не в первых версиях.

**Что не сделано и почему**
- Качество поиска не измерено ни для одного варианта: в репозитории нет размеченного набора картинок и запросов, онлайн-ключей в среде нет. Нужен PoC с 20 запросами (русский и английский) и 50 картинками.
- Цена картинки у мультимодальных моделей не ясна: в каталоге у `gemini-embedding-2` цена за единицу без описания, у `titan-embed-image-v1` — за картинку (не проверено). Уточнить вызовом с ключом владельца.
- Android и iOS: ONNX Runtime в мобильных сборках и размеры в пакете не проверены (нет устройств).
- `sqlite-vec` под .NET не проверен.

**Вопросы владельцу** (в ADR 0016 и в `docs/status.md`): согласие на отправку картинок провайдеру; модель текста (bge-m3 или text-embedding-3-small); провайдер картинок; нужен ли офлайн-режим; переиндексация — сразу или в фоне. После ответов — задачи реализации (`scripts/new-task.sh --publish backlog …`).
