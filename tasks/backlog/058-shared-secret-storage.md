# Подумать: общее хранилище ключей для оболочек

## Описание
Владелец (2026-10-28): хранилище ключей выглядит как то, что должно быть общим. Решение отложено («сложный выбор, подумать, как лучше»). Задача — сначала разобрать варианты и предложить решение владельцу; код — только после выбора и отдельного плана.

Зависит от: —.
Среда: любая (разбор и документ); реализация — по итогам.

## Критерии готовности
- Сравнение вариантов (ниже и, если найдутся, другие): что выносится, кто пользуется, что меняется для пользователя (общий ли ключ у MAUI и Avalonia на одной машине), стоимость, риски, тесты.
- Рекомендация и вопросы владельцу в «Комментариях»; после выбора — ADR (уточняет или заменяет ADR 0008) и план реализации в этой задаче или новой.

## Анализ
- Сейчас: `ISecretStore` — в ядре (`ImageGen.Core/Platform`). Реализации:
  - MAUI — `MauiSecretStore` поверх `SecureStorage` (около 30 строк; Android Keystore, iOS и macOS Keychain, Windows — шифрование MAUI);
  - Avalonia — `ImageGen.Avalonia/Services/Secrets/`: `DesktopSecretStore`, `DpapiSecretBackend` (Windows), `SecretServiceBackend` и `SecretServiceDBus` (Linux, `Tmds.DBus`), `KeychainSecretBackend` (macOS, утилита `security`, не проверен), `SecretFileNames`, запасной вариант в памяти (ADR 0008); около 400 строк, тесты в `ImageGen.Avalonia.Tests/Services/Secrets/`.
- Код Avalonia-хранилища не использует типы Avalonia: только DPAPI, D-Bus, `security`, `IAppPaths` и `ISecretPersistenceInfo` (Presentation). Вынести его технически просто.
- У MAUI и Avalonia разные папки данных и разные ключи на одной машине (решение владельца 2026-10-28, задача 039). Общий ключ потребовал бы и общего места хранения.
- Будущая Web-оболочка хранит секреты в файле под ASP.NET Core Data Protection (`docs/status.md`, решения владельца) — третий способ.

Варианты, заданные владельцу 2026-10-28 (ответа нет):
1. Новый проект `ImageGen.Desktop` с этим кодом; им пользуется Avalonia везде и MAUI на Windows и macOS (на Android и iOS остаётся `SecureStorage`).
2. Тот же проект `ImageGen.Desktop`, но MAUI остаётся на `SecureStorage` везде; выигрыш — код не привязан к UI-фреймворку и тестируется без Avalonia.
3. Один слой ключей с выбором реализации по платформе для всех оболочек (десктоп — DPAPI/Secret Service/Keychain, телефоны — `SecureStorage`, Web — Data Protection) за тем же `ISecretStore`.

## План

Разбор без кода. Шаги: 1) описать текущее хранение ключей в обеих оболочках (ADR 0008, `MauiSecretStore`); 2) сравнить варианты A/B/C по критериям задачи; 3) отметить непроверенное; 4) рекомендация и вопросы владельцу; ADR после выбора.

## Отчёт

Разбор вариантов выполнен (`claude-536f`, 2026-10-29). Решение владельца не принято, код не написан: по задаче — ADR после выбора.

**Что сейчас.** Две оболочки на одной машине хранят ключ отдельно. Avalonia — `DesktopSecretStore` (ADR 0008): Secret Service на Linux, DPAPI-файл в папке данных на Windows, Keychain на macOS (не проверен). MAUI — `SecureStorage` через `MauiSecretStore`. Папки данных разные (`ImageGen` и папка MAUI), поэтому ключи и так не общие. Статус из `docs/status.md`: «у MAUI и Avalonia на одной Windows-машине разные папки данных и ключи».

**Варианты**

| Вариант | Что выносится | Кто пользуется | Что меняется для пользователя | Стоимость | Риски |
|---|---|---|---|---|---|
| A. Оставить раздельно | ничего | каждая оболочка отдельно | ключ вводится в каждой оболочке один раз | 0 | два места для смены ключа; ключ нужно ввести дважды |
| B. Общий файл в общей папке | DPAPI-файл или зашифрованный файл в общей папке | обе оболочки, одинаковые ключи | ключ вводится один раз; папка MAUI меняется или читается с миграцией | средняя: общая папка и миграция данных MAUI | связано с `ApplicationId` (задача 030): смена меняет папку данных Windows; общая папка видна обеим программам |
| C. Системное хранилище пользователя | ключ в Windows Credential Manager, Keychain, Secret Service с общим именем службы | обе оболочки; ключ не лежит в папке приложения | ключ вводится один раз на машине | высокая: MAUI нужна своя реализация вместо `SecureStorage` на Windows и macOS; новая зависимость или P/Invoke (ADR) | на Linux без Secret Service — память, как сейчас; дважды решать одинаковые вопросы |

**Что проверено по документации.** ADR 0008 (Avalonia: Secret Service и DPAPI на Windows, Keychain не проверен). Текущий интерфейс `ISecretStore` в обеих оболочках.

**Что не проверено.** Поведение `SecureStorage` MAUI на Windows и macOS при общем имени службы; возможна ли одновременная запись из двух процессов; Keychain на macOS (нет машины).

**Рекомендация.** Вариант A на текущем этапе: пользователь вводит ключ один раз в каждой оболочке, безопасность не меняется, работы нет. Вариант C — если владелец хочет один ключ на машине: он самый чистый, но требует работы в MAUI и решения по зависимостям (ADR). Вариант B не рекомендую: общая папка и миграция дают те же риски, что и C, без выигрыша.

**Вопросы владельцу**
1. Нужен ли один ключ на машину для обеих оболочек (вариант C), или достаточно ввода в каждой оболочке (A)?
2. Если C — принимаете ли новую реализацию `ISecretStore` для MAUI на Windows и macOS (ADR)?
3. Сначала решить с `ApplicationId` (030), потому что он меняет папку данных на Windows?
