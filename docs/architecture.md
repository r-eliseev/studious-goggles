# Архитектура

Статус: целевая раскладка предложена (`docs/decisions/0001-core-and-heads.md`), в коде её пока нет. Единственный код в репозитории — проект-пример `ImageGen/`; его устройство описано в разделе «Состояние кода» и подробно в `docs/knowledge/example-patterns.md`.

## Целевая раскладка (предложено)
Схема из заметок владельца: общее ядро и несколько оболочек. Названия проектов рабочие.

```
ImageGen.Core            net10.0, без UI-зависимостей
  Providers/             fal, Replicate, OpenRouter за общим интерфейсом провайдера
  Generation/            Text2Img, Img2Img, Img2Text; единая модель задания и статусов
  Config/                Secrets (шифрованное хранилище), Preferences (настройки)
  Results/               репозиторий результатов (БД + файлы) за интерфейсом
ImageGen.Core.Tests      тесты ядра
ImageGen.Maui            Android, iOS, macOS (Mac Catalyst), Windows; страницы и PageModels
ImageGen.Web             ASP.NET Core Web API + статический Vue-фронт, Docker
```

## Слои и зависимости
- `Core` не ссылается ни на MAUI, ни на ASP.NET Core, ни на какие UI-типы (`Brush`, `Color`, `Shell`, `Preferences`, `FileSystem` из MAUI Essentials). Платформенные вещи приходят через интерфейсы, объявленные в ядре: хранилище секретов, хранилище настроек, папка данных, сохранение в галерею.
- `Maui` и `Web` ссылаются на `Core` и реализуют его интерфейсы своими средствами.
- Страницы (`Pages`) знают только свой `PageModel`; `PageModel` знает ядро и сервисы, но не страницы и не XAML-типы, кроме навигации через `Shell` (как в примере).
- Оболочки не ссылаются друг на друга.
- Правила слоёв надо проверять автоматически (тест на ссылки сборок или архитектурный тест) после появления проектов, а не только при аудите.

## Потоки данных
Основной сценарий (из спецификации): пользователь выбирает набор моделей и вводит промпт → оболочка вызывает ядро → ядро для каждой модели создаёт задание и отправляет его провайдеру параллельно и независимо → статусы заданий приводятся к единой модели (в очереди, идёт, готово, ошибка, отменено, отфильтровано) → готовая картинка сразу скачивается и сохраняется в репозиторий результатов → оболочка показывает карточку с моделью, временем и ценой.

Различия провайдеров, которые ядро скрывает (подробно в таблице спецификации): fal работает через очередь, Replicate через асинхронные предсказания, OpenRouter отвечает синхронно с картинкой в base64. Секреты в запросах: ключ читается из хранилища секретов в момент вызова и не попадает в журналы и экспорт (F10.3).

## Внешние системы
fal.ai, Replicate, OpenRouter (HTTP API). Хранилища на устройстве или сервере: локальная БД и файлы результатов, зашифрованный файл секретов. Docker: образ Web-оболочки.

## Состояние кода: проект-пример `ImageGen/`
Это MAUI-приложение «проекты и задачи» (шаблон), а не клиент генерации изображений. Один проект `ImageGen/ImageGen/ImageGen.csproj`, `SingleProject`, целевые платформы Android, iOS, Mac Catalyst, Windows (Linux в шаблоне нет). Слои внутри проекта:

| Каталог | Что внутри |
|---|---|
| `Data/` | репозитории на `Microsoft.Data.Sqlite`, сидирование из `Resources/Raw/SeedData.json`, `JsonContext` |
| `Models/` | POCO-модели, часть с UI-типами |
| `PageModels/` | MVVM-логика на `CommunityToolkit.Mvvm` |
| `Pages/`, `Pages/Controls/` | XAML-страницы и переиспользуемые контролы |
| `Services/` | обработчик ошибок для UI |
| `Utilities/` | расширения |
| `Resources/` | стили, цвета, шрифты, иконки, сырые ассеты |
| `Platforms/` | точки входа и манифесты платформ |

Что переиспользовать, а что нет, расписано в `docs/knowledge/example-patterns.md` (разделы «Брать» и «Не переносить»).

## Ограничения
- Платформы: MAUI не поддерживает Linux (см. `docs/status.md`).
- Безопасность: ключи провайдеров только в шифрованном хранилище; в Web-варианте доступ закрыт паролем из переменной окружения; ключи и пароль не попадают в журналы, экспорт и репозиторий.
- Производительность: задания идут параллельно, UI не блокируется, карточки резервируют место сразу (сетка не прыгает).
- Совместимость: ссылки результатов провайдеров живут от часа, поэтому файл сохраняется сразу.
