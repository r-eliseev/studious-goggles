RISKS
1. Changing `CultureInfo.CurrentCulture` in a test is thread-bound. If `RefreshAsync` continues after an `await` on another thread (no sync context in a test runner), `CurrentCulture` set on the test thread may not apply. The test could then pass or fail for the wrong reason. Setting `CultureInfo.DefaultThreadCurrentCulture` may be needed, but the plan does not mention it.
2. Tests that change culture can affect other tests running in parallel (xUnit or MSTest parallelism), even with the `finally` restore. The plan does not say whether the test class is excluded from parallel execution.
3. On Linux, `ru-RU` can be missing if the environment uses invariant globalization (`InvariantGlobalization=true` or no ICU). Then `CultureInfo("ru-RU")` throws or behaves as invariant, so the test cannot fail before the fix and does not prove anything. The spec lists Linux and Windows as the environment.
4. The plan duplicates the `CostTextOf` formatting, and task 186 will later remove the duplication. Until then, a change to `CostFormat` or to the `0.####` rule must be made in several places, and the new test only covers the spending screen.
5. `dotnet format --verify-no-changes` and `scripts/check.sh` may fail on pre-existing formatting problems or on other checks. The order instruction does not say whether a failure unrelated to this change should stop the work or be reported.
