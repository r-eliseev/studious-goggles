5. Is `ShowActionsCommand` meant to be disabled in the error and filtered states, or only when `IsFinished` is false? The criteria say "доступна, когда IsFinished", which excludes those states but the design shows Repeat there.
6. Where do the "Тесты из «Плана»" for the MAUI long-press and "…" button live, given the Verify section only builds MAUI for Android and has no MAUI test project?

RISKS:
1. Step 2 places the `card-actions` stack inside a `Border.card` and relies on `:focus-within`; Avalonia does not support `:focus-within` as a pseudo-class, so the focus-visible requirement may silently fail and the `Actions_VisibleOnFocusWithin` test will not catch it.
2. The `ContextMenu` on the card and the "More" button opening the same menu requires a shared resource or binding; in Avalonia a `ContextMenu` set on the `Border` is not reachable from a button in a `DataTemplate` without explicit binding, which the plan does not address.
3. Step 3's `LongPressCommand` on a `TouchBehavior` may conflict with the `Button` or the `TapGestureRecognizer` that handles the card's normal tap, and the plan does not say which element receives the gesture.
4. `DisplayActionSheet` in MAUI is async and can throw or return null if the page is not the current Shell page at the moment of call; the plan does not address this with `Shell.Current` being null or during navigation.
5. Step 1 says tests with `ShowActions_ChoosesRepeat_RunsRepeat` will pass after changing the dialog double, but `Repeat` may itself be guarded by `IsFinished` or running state, so the expected behaviour in the test may not match the actual command.
6. The Verify list contains `dotnet format ... --verify-no-changes` only for three projects but not the Avalonia test project, and `dotnet build` for Android only, so Windows `MenuFlyout` code is never compiled in the stated checks.
7. If the mandated `blocked` path is reached in step 2 or 3 (e.g. missing API), the plan gives no guidance on whether the Presentation changes from step 1 should be kept or reverted, leaving the repository in a partial state.
