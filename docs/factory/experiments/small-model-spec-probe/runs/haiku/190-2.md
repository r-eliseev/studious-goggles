**ASSUMPTIONS**

1. Only one application process writes to the data folder at a time. If two instances run, the cleanup in step 2 can see another live process's temp file, and only the one-hour age check protects it.
2. A live write always updates the temp file's last-write time, so a write in progress never looks older than one hour. The spec's "младше часа — запись может идти" depends on this.
3. `FileImageStore` knows the data-folder root (where `defaults.json` lives) and the `images/` path. Step 2 scans both, but the spec never says how the store gets them.

**QUESTIONS**

1. Analysis says "в фоне", but step 4 uses `await Task.Run(...)` inside `InitializeAsync`, which blocks startup until the scan finishes. Should startup wait for the cleanup or not?
2. The Warning requirement needs a logger in `FileImageStore` (Data) and in the `IImageFileStore` contract (Core). Step 4 does not mention a logger, so how should the Warning be emitted without exceeding the plan?
3. Should a missing `images/` folder be silent? `Directory.EnumerateFiles` throws `DirectoryNotFoundException` there, and the spec only says "без ошибки" without saying whether a Warning is allowed.

**RISKS**

1. The `AllDirectories` enumeration can throw midway (for example, access denied on one session folder). If the `try` wraps the whole walk, the scan stops and "обход продолжается" is violated. Errors need handling per directory and per file.
2. If the system clock jumps forward by more than an hour, or `TimeProvider` and file timestamps come from different sources (network shares, Android storage), fresh temp files from an active write can be deleted. A backward jump fails safe.
3. A writer that stalls for more than an hour but is still alive loses its temp file. On Linux the unlink succeeds, and the writer's `File.Move` then fails with `FileNotFoundException`, so the save fails. On Windows the delete fails with a sharing violation and the file gets a Warning on every startup, with no cap on repeated warnings.
4. The acceptance criterion "ошибка удаления — Warning" has no test in the plan. The Data tests create files on Linux, where locked-file failures are hard to reproduce, so this path is untested.
