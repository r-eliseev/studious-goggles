ASSUMPTIONS:
1. The spec's "ScrollTo(индекс, ScrollToPosition.End)" on MAUI `CollectionView` is assumed to reliably land the last card's bottom edge in view; the spec itself admits the last index does not prove the bottom edge is visible, yet the plan relies on it.
2. `Transcript` name in the Avalonia test (`FindControl<ScrollViewer>("Transcript")`) is assumed to exist in `ChatView.axaml`; the spec never states the XAML name is already "Transcript".
3. The Avalonia `ScrollChanged` event is assumed to fire for layout-driven extent changes with `OffsetDelta.Y == 0`, which the filter depends on; this is not stated.
4. The spec assumes `ChatPageModel.Items` in MAUI is accessible from the page code-behind and that `Items` changes are raised on the UI thread.
5. The MAUI row-template `SizeChanged` handler is assumed to be attachable in XAML/DataTemplate without touching the data model, with no mention of how the handler reaches the page instance.

QUESTIONS:
1. Item 1 of "Решения" says any `Items` change scrolls to end even when the user scrolled up, but the MAUI step 7 `OnItemsChanged` routes through `RowsChanged()`, which also always follows; should the "Повторить"/"Новый seed" reset also clear the user's scroll-up state, and where is that documented?
2. Step 7 says `OnTranscriptScrolled` with `VerticalDelta < 0` always sets `UserScrolled(false)`, but "Решения" item 3 only says scroll-up disables follow; is any threshold or drag-vs-fling distinction intended, given that momentum scrolling can produce small negative deltas?
3. Step 4 Avalonia says `ScrollChanged` with extent/viewport delta requests scroll "только если follower уже следовал", but this conflicts with the acceptance criterion that the list stays at end after content growth when the user had not scrolled; which field defines "уже следовал" at that moment?
4. The criteria say "при открытии сессии лента стоит в конце", yet step 3 test `OpenChat_LongHistory_TranscriptAtEnd` and step 7 `OnAppearing` both depend on `RowsChanged()` being called before load; what happens if the model is already loaded and `Items` does not change?
5. Is the 40-message Avalonia fixture sufficient to guarantee the list overflows the viewport at 1000px height, and what is the expected viewport size in headless tests?

RISKS:
1. Step 7 `ScrollTo` with `animate: false` on MAUI Android may still be ignored if called while the `CollectionView` has not finished layout after `Items` reset; the spec does not require a layout-pass check or retry.
2. The `_programmaticScroll` guard on MAUI is described as reset "после отложенного UI-dispatch", which may swallow a genuine user scroll that arrives in the same frame, and the guard is not tied to a specific event.
3. The `Scrolled` event on MAUI `CollectionView` fires with `VerticalDelta` relative to the previous position; a fling that starts at the end and reverses can misclassify direction, and the spec does not address overscroll bounce at the bottom.
4. Step 7 `OnAppearing` unsubscribes and resubscribes `_model.Items.CollectionChanged` before `OnAppearingAsync`, but `OnDisappearing` also unsubscribes; if `OnDisappearing` is not called on navigation pop in MAUI Shell, handlers may stack, and the spec's "повторное OnAppearing не создаёт двойных реакций" only covers the reattach, not the leaked model reference.
5. `ScrollToEndLater` on MAUI captures `_model` in the dispatched lambda; if the page is disposed or `_model` is reassigned before the callback runs, it may scroll a stale model; the spec says to check `_active` but not to recheck the model identity.
6. Avalonia `ScrollToEndLater` with `_scrollPending` coalescing: if `_active` goes false and back true within one dispatch, the pending callback may run once for the new session without the reset being applied, leaving the follower state from the old session.
7. Step 2 raises `CardUpdated` after `card.Update` inside `BeginInvokeOnMainThread`, but the spec's own analysis says the image layout happens later, so the follower will scroll before the new height exists; the image-load growth path depends entirely on the MAUI `SizeChanged` hook in step 7, which is untested on device until step 140.
8. The plan mandates TDD and an Android SDK build but says a missing SDK can be "подготовлен по docs/knowledge", and CI for Windows; an executor model may fail the Android build silently or mark the task done without it, which the spec does not guard against beyond "blocked".
