**ASSUMPTIONS**

1. The spec assumes the only producers of these temp files are `AtomicImageFileWriter` and `DefaultAssistantModelFile.SaveAsync`, and that no user-visible final file name can match `^\..+\.[0-9a-f]{32}\.tmp$` or `^defaults\.json\.[0-9a-f]{32}\.tmp$`.
2. The plan assumes `images/` contains only app-written session subfolders and that the data-folder root is the same directory `DefaultAssistantModelFile` writes to. The spec never says how `FileImageStore` learns that root.
3. The plan assumes one app instance owns the data folder at startup. The spec does not mention a second instance (Avalonia, Maui, or a test host) pointing at the same folder.

**QUESTIONS**

4. Step 2 says the cleanup runs "в фоне", but step 4 awaits `Task.Run(...)` inside `InitializeAsync`, which blocks startup. Which is intended? Step 3 also names `EnsureInitializedAsync` while step 4 names `InitializeAsync`. Which method is the hook?
5. The spec requires a Warning with file name and exception type, but does not say how the Data layer emits it. Does `FileImageStore` get a logger, and through which abstraction? How will the Presentation test observe the warning?
6. Does "старше 1 часа" mean strictly greater than the threshold? What should happen to files whose timestamp is in the future (clock skew), which the `now - lastWrite > olderThan` rule would never delete?

**RISKS**

7. Only the per-file delete is wrapped in the error handling. Enumeration of `images/` with `Directory.EnumerateFiles(..., AllDirectories)` is lazy and can throw mid-iteration on an unreadable subfolder or a folder removed concurrently. That would fail startup, contrary to the "запуск не падает" criterion.
8. Age is judged by `File.GetLastWriteTimeUtc` against the injected `now`. A forward system clock jump (NTP correction, manual change, VM resume) can make a fresh in-progress temp file look older than one hour and delete it.
9. If a writer is still alive (a second instance, or a write stalled for more than an hour), deleting its temp file makes its later `File.Move` fail. The spec does not say how the writer behaves in that case, so the failure mode is undefined.
10. Adding a member to `IImageFileStore` and making `AppInitializer` depend on `TimeProvider` changes its constructor. Any construction site the plan's `rg` search misses, such as the Avalonia `ShellHarness` or DI-resolved hosts, will fail to compile or silently get different behaviour.
