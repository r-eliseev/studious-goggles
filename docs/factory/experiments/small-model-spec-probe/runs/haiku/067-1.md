**ASSUMPTIONS**

1. Items 066 and 072 are assumed to be finished: the left-column markup being moved, the `ConfirmAsync(..., destructive: true)` overload, and the `SessionsPageModel` singleton all come from them, but the spec gives no state for either, and Steps 0 and 3 depend on them.
2. The 840 threshold is assumed to apply to window width in dp on both platforms. The spec does not say whether it is window or control width, which matters because the 272 px list is part of the same row.

**QUESTIONS**

3. What happens to an image generation running in the current chat when the user selects another session or presses "New session": is it cancelled, left running, or blocked? The spec defines no state transitions for the chat being replaced.
4. On the wide layout there is no list screen to return to, so what does "назад" do from the chat? The criteria only define narrow-layout back behaviour, and `GoBackAsync` is tested only in Avalonia.
5. When the open session is deleted on the wide layout, which session becomes current, or does the chat area go blank? The spec also does not say what the chat area shows when there are no sessions or no current session.
6. Step 2 leaves the navigation method open ("если нужен", "выбрать при реализации"), and the choice of route form is deferred to the implementer. It also does not say whether `ChatPageModel` is transient or singleton, which determines what "replace" and the tracker mean.
7. The Files list includes `Pages/SessionsPage.xaml`, but no plan step changes it, while the criteria require the list screen (066) to use `SessionsListView`. Is the MAUI list screen migration in scope?

**RISKS**

8. One `SessionsPageModel` instance shown in both the list screen and the chat's embedded list can be attached twice when old pages remain in the navigation stack, so selection, scroll position and focus may be shared between the two views.
9. `ChatPageModel` loads asynchronously. If the user selects session B while session A is still loading, A's late `SetCurrent` can overwrite the highlight and leave the wrong item marked as current.
10. In MAUI Shell, the two route forms named in the spec behave differently: absolute routes reset the hierarchy and may recreate pages, while relative routes keep the previous `ChatPage` on the stack. The "no stack" criterion is therefore not guaranteed by the platform, and the MAUI replacement has only a build check, no test.
