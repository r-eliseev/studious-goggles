**ASSUMPTIONS**

1. The spec assumes one app instance per data folder. A second instance, or a write stalled for more than an hour, could have its live temp file deleted by the sweep, and the spec does not address this.
2. The spec assumes `FileImageStore` can log Warnings, but it does not say how the Data layer gets a logger. `FileImageStore` is not listed as taking a logging dependency.

**QUESTIONS**

1. The Analysis says the sweep runs "в фоне", but step 4 has `InitializeAsync` `await Task.Run(...)`. Does startup wait for the sweep to finish, or should it run without blocking?
2. "Старше 1 часа" and `olderThan` do not specify the comparison: is a file exactly one hour old deleted (`>` or `>=`)? Does age come from last write time only, as the Analysis states, or should creation time also be considered?
3. Step 5 says to fix manual `new AppInitializer` calls, and the Analysis asks whether `ShellHarness` creates it manually, but the spec does not resolve this. Should Avalonia tests be changed or only verified?
4. The Data-level test setup in step 1 uses the data folder root for `defaults.json`. Is that root always the same folder that `DefaultAssistantModelFile` writes to, or can its path be configured elsewhere?

**RISKS**

1. The acceptance criterion "запуск не падает" covers only per-file errors. `Directory.EnumerateFiles(..., AllDirectories)` can throw `UnauthorizedAccessException` or `DirectoryNotFoundException` mid-enumeration, which would abort the whole sweep and, if not caught, propagate out of `InitializeAsync`.
2. Awaiting a full recursive scan of `images/` during initialization adds startup latency that grows with the number of sessions and images. On a slow or network-backed disk it can delay or stall app startup.
3. Between enumeration and `File.GetLastWriteTimeUtc` (or `Delete`), a writer can rename its temp file to the final name, which throws `FileNotFoundException`. Files still held open on Windows will fail to delete. Both cases produce a Warning on every launch, and the spec does not say whether these should be silent.
4. The age check relies on the wall clock. A clock set backwards can make an in-progress temp file look older than an hour and get deleted, and a file with a future timestamp is never removed. The spec does not address either case.
