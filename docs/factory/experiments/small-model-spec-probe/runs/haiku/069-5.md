ASSUMPTIONS

1. The "Описание" and "Критерии" sections say the bottom menu on phones is opened by "…" and long press, but the Plan's step 3 says MAUI "…" is visible only on phones, while the Criteria say "на Windows и Mac — видимая кнопка «…»". I assume the "…" button is visible on every MAUI platform and only long press differs, or that it is hidden on phones; the spec doesn't say which.
2. "Dictionary" keys (`docs/design/implementation.md`) and the tokens/icon names (`Repeat`, `NewSeed`, `Edit`, `Describe`, `More`) are assumed to exist and match the prototype exactly; the spec says "дословно оттуда" but the file was not provided.
3. The step-by-step plan assumes `GenerationItemViewModel` already exposes `ModelText`, `SeedText`, `CostText`, `TimeText` and `IsFinished` with those exact names.
4. Error and filtered cards ("У ошибки и отфильтрованной — кнопка Repeat всегда видна") are assumed to be handled by the same `ShowActionsCommand` / `IsFinished` gate, or by a separate element; the spec doesn't say whether the Repeat-only button needs its own command.

QUESTIONS

1. Step 1 gates `ShowActionsCommand` on `IsFinished`, but the criteria say Repeat must always be visible on error and filtered cards. Are error and filtered items "finished" for this command, or does the menu need a different gate?
2. Is the "…" button on MAUI shown on all platforms, or only on phones? The Criteria say both "на телефонах" and "на Windows и Mac — видимая кнопка «…»", which reads as an explicit contradiction with the phone-only long-press description.
3. Is the bottom action sheet title (model · seed · cost · time) also the title shown on the Avalonia `ChooseAsync` window, or only on MAUI? The interface signature takes one `title` string, so the Avalonia dialog shape is unspecified.
4. What should happen with `ChooseAsync` when the user dismisses the Avalonia dialog or taps outside it: does it return `null` as the cancel path, and is `cancel` shown as a button?
5. "Тесты из «Плана» проходят" and the test names in step 1 are listed, but the expected behaviour for `ShowActions_NotFinished_CannotExecute` is unclear: should `ShowActionsCommand.CanExecute` be false, or should `ChooseAsync` never be called?
6. Which ADR 0014 decisions apply, since the spec only links to it? In particular, is there a rule on whether MAUI uses `ContextFlyout` on desktop-class Windows builds that also run Android?
7. Dependencies 068 and 072 both change `AvaloniaDialogService`; is there an agreed order, and does this task need to rebase on whatever they change?
8. Step 3 says the long-press uses `CommunityToolkit.Maui` `TouchBehavior.LongPressCommand`, but the text ends with "проверить версию". Which version is pinned, and does `LongPressCommand` exist in it? If not, what is the fallback allowed by the plan?

RISKS

1. Step 2's style selector `Border.card:focus-within` is not a standard Avalonia selector. Avalonia has no `:focus-within` pseudo-class, so the "visible on keyboard focus" criterion may not be achievable as written, and the plan has no fallback beyond "stop and report".
2. Hiding the icon row with `IsVisible` toggled by `:pointerover` means the buttons are removed from the visual tree and accessibility tree when hidden, so `IconButtons_HaveAutomationNames` and keyboard tab order may fail or behave inconsistently; `Opacity` or keeping focusable would be a different design.
3. Long press with `TouchBehavior.LongPressCommand` on a card that also contains buttons and scrolls in a `CollectionView` can conflict with scroll gestures and with the button taps themselves, and the plan does not address this.
4. `DisplayActionSheet` (MAUI) is asynchronous and modal; calling it from a command while another modal is open, or when `Shell.Current` is null during navigation, will throw or return immediately; the plan does not say how `ShellDialogService` gets the current page.
5. Avalonia `ContextMenu` on the card and the "More" button both must open the same menu; if the card's `ContextMenu` is bound to the `DataContext`, the "More" button may open it against the wrong item in a virtualised list, or open it with a stale `IsFinished` state.
6. `ChooseAsync` returning `string?` with localized labels as the identity of the chosen action makes the logic fragile: two actions with similar or duplicate labels, or a label change, will map to the wrong command; the plan does not suggest an enum or index.
7. `ShowActionsCommand` is async; if the item's state changes (e.g. generation finishes or is re-run) while the sheet is open, the chosen action runs against a stale state; no cancellation or re-check is specified.
8. The verification command `dotnet build ... -f net10.0-android -p:AndroidSdkDirectory=$ANDROID_HOME` depends on the Android SDK and workloads being installed on the Linux agent; if they are missing, the MAUI step cannot be verified, and the plan says to stop only when a step "не получается так, как написано", not when the environment is missing.
