ASSUMPTIONS
1. `CostTextOf` and `ChatPageModel.FormatEstimate` use exactly the same pattern (`0.####` + `InvariantCulture` + `AppResources.CostFormat`), so "как в CostTextOf" is a faithful reference. The spec only names `CostTextOf` and does not show its code.
2. The journal sums are `decimal` or `double`, and the `0.####` format rounds to 4 decimals. The spec does not say whether rounding of the total should happen before or after summation.
3. `$0` for zero follows from `0.####` producing an empty string or "0" for zero, which the spec does not confirm; the zero case is a separate expectation that needs its own check.
4. `AppResources.CostFormat` is a resource that is not localized per culture, so passing `InvariantCulture` is enough to keep the `$` literal stable in every locale.

QUESTIONS
1. The acceptance criteria say "сумма в формате `0.####`", but the plan's test expects `$0.0345` from 0.03 + 0.0045. Should the total be rounded to 4 decimals, or shown with all significant digits, for example when the sum is 0.00001?
2. The spec does not say whether `TotalText` must match the per-row or per-group formatting, or whether it is only the top-line total. Is the chosen format also expected in group totals (`SpendingGroup.TotalUsd`)?
3. What should `TotalText` show when there are no journal rows in the period at all? The spec only covers zero as a sum, not an empty set.
4. The plan says the test should use `ru-RU`, but the spec does not say whether the tests should also cover `CurrentUICulture` or other cultures with different decimal separators (e.g., `de-DE`), which would make the defect more visible.
5. The spec says "Файлы" are only `SpendingPageModel.cs` and its test, but the plan says the signatures must be checked against `main`. Is the current `main` state the baseline, or the state at PR #70?

RISKS
1. Culture is set via `CultureInfo.CurrentCulture` in the test, but `string.Format` and `ToString` may use `CurrentUICulture` for resource lookup of `AppResources.CostFormat`, so the test could pass or fail depending on which culture the resource manager uses. Verify this with the actual resource loader.
2. Restoring culture in `finally` is required, but if the test runs in parallel with other tests in the same process, changing `CurrentCulture` can leak into them (xUnit/NUnit parallelism). The plan does not mention isolating this test.
3. Using `0.####` drops trailing zeros and shows an empty string for exactly 0 in some formats, so the criterion "ноль → `$0`" may actually show `$` alone. This needs an explicit test, not only the 0.0345 case.
4. Sums of `double` values from the journal can produce floating-point residue (e.g., 0.030000000000000002), which `0.####` rounds, but comparisons in tests against exact strings may be fragile if the rounding mode is not specified.
5. If the `TotalText` binding is recomputed on culture change at runtime, the `$` format may differ from the one shown at load, so behaviour across culture switches is untested.
6. The `dotnet format --verify-no-changes` step might fail on unrelated files if the repo has pre-existing formatting drift; the plan does not say how to handle that.
