## 1. disler/super-simple-software-factory (SSSF)

**Size:** ~13.9k lines, ~100 files, all under `.claude/skills/sssf/`; Python ~3.6k LOC, TS/Vue ~5.4k (visualizer app), Markdown ~2.2k. No tests directory anywhere. `scripts/`: `install.py`, `make_adw.py`, `make_config.py`; `templates/adws/` has 13 ADW scripts and `adw_modules/` (agents, runner, permissions, gates, quality, tracer, data_types, agent_pi, git_helper, changes, session, console, prompts, utils, agent_cc); prompts for planner, builder, reviewer, scout, documenter.

**Skill:** `SKILL.md` is a behavior contract for the operator session: reads an overview, lists each ADW's `Phases:` docstring, prints a table, waits; forbids volunteering state or querying the DB (a previous orchestrator invented tables that do not exist); never does ADW work itself; lazy-loads one cookbook per request type. Ten hard rules, among them: validate agents before running; typed envelopes with a "synced triad" (type in `data_types.py`, JSON example in `user.md`, `output_type=` at the call site); gates check claims; at most 4 params per function; one agent, one prompt; known commands are code, not agents; `writes:` and `protected_files` are enforced; every ADW ends in `run.finish(accepted=)`.

**Install:** `install.py` is plain `shutil.copy2`; skips existing destinations unless `--force`; appends missing runtime entries to `.gitignore`. No merge, so template changes never propagate without `--force`.

**Engine:** an ADW is a Python script: `REQUIRED_AGENTS`, `agents.load_config` + `agents.validate`, `session.ensure` -> `Run`; each phase is `with run.phase(PhaseParams(name, kind, owner, description, retries))` (`kind`: engineer, agent, code). `Run.phase` (`runner.py`) defaults to fail and flips to success only on clean exit; an exception records the error, fails the session and re-raises. A validator rejects empty phase descriptions and ones that restate the name. Control flow is plain Python loops (`adw_simple_sdlc`: plan, commit plan, build, up to 3 test/fix rounds, up to 2 review/revise rounds, retest, commit, changes, document; ends in `run.finish(accepted=verified)`). Agents run as `pi -p --mode json ...` via `subprocess.Popen` (`agent_pi.py`), stdout tailed as JSONL; `validate()` calls `pi --list-models`. Envelope parsing: `_extract_json` (first fenced block starting `{`, else first `{` to last `}`) validated against a pydantic `output_type` (`EnvelopeBase`: status, summary, artifacts, notes_for_next_agent); on failure `_parse_with_retries` re-prompts the same pi session up to `JSON_FIX_ATTEMPTS=2`; gate violations use the same route bounded by `phase.params.retries`, then `GateFailure`.

**Gates (actual checks):** `artifacts_exist`; `files_non_empty`; `json_parses`; `diff_matches_claims` (only checks that each path in `changed_files` **exists**, not that it changed); `verdict_consistent` (review `approved` vs `blocking` list and unmet findings); `tests_pass(command)` (runs a shell command with `shell=True`). `quality.py` blocks (`test`, `lint`, `typecheck`, `build`) all ship as `_placeholder` echoes that exit 0, so a fresh install's tests are vacuous (the README admits it).

**Permissions (`permissions.py`):** detective, by diffing the working tree: `snapshot` fingerprints `git diff HEAD --numstat` plus untracked files; `agents.execute` snapshots before the first send and calls `enforce` after retries and gates; a reverted path counts as changed. `permitted()` order: `data_dir/` always allowed; agent `writes` match allows (and unlocks protected files); `protected_files` match denies; otherwise allowed only if `writes is None` (`[]` = read-only). Rollback: untracked file unlinked, tracked file `git checkout -- path`, a path already dirty before the call is left alone (reported if the agent reverted it). Then `PermissionBreach` kills the phase (never retried). Limits: writes outside the repo or to gitignored paths are invisible; edits to an already-dirty file are caught only if numstat counts change; the agent's bash is unsandboxed.

**State (SQLite via `tracer.py`, WAL):** tables `sessions`, `phases` (status default `'fail'`), `events`, `envelopes`, `gate_results`, `processes`, `agent_sessions`; on disk `adws/adw_data/sessions/<adw_id>/` (`agent_map.json`, `context_handoff/`, per-agent prompts, raw output, envelope, pi sessions). A rejoined `--adw-id` resumes agent context only if the model is unchanged. The visualizer polls the DB at ~500 ms.

**README vs code:** README is mostly honest (`claude_code` is a 15-line stub that raises; quality placeholders). `SKILL.md` says the visualizer ships "in a later pass", but it exists. Config names models/providers (`kimi-k3`, `gpt-5.6-terra`, `gemini-3.6-flash`) the helper could not verify. Zero tests for the harness itself.

**Worth borrowing:** (1) post-hoc permission enforcement by tree diff with per-role `writes` (planner only `docs/`+`tasks/`; executor not `scripts/` or `.github/`); (2) typed envelopes with self-consistency gates and corrections fed back into the same session, bounded; (3) acceptance separated from phase success (`run.finish(accepted=)`), known commands as code, failures wrapped as envelopes, commit the plan before code.
**Weaknesses:** enforcement is detective only and the existence-only claim gate proves little; depends on an external CLI and model JSON discipline, and task state lives in SQLite and scripts, not in reviewable repo files; install is copy-and-skip with no upgrade path, `tests_pass` uses `shell=True`, default test phase passes vacuously.
**Not verified:** no runtime behavior (pi JSON format, SQLite concurrency, rollback correctness, visualizer); `session.py`, most of `data_types.py`, cookbooks, other ADW scripts and the visualizer source were not read.

## 2. dwightfowler-tema/factory-setup

**Size:** ~5.2k lines, 36 files (GPLv3 text included), `VERSION` 0.4.0; shallow clone has one commit. `SKILL.md` (41 lines), `INSTALL.md` (186), `scripts/factory_setup.py` (877, stdlib only), `payload/` (the factory), `templates/` (checks for go, make, node, python, python-uv, rust, and an AGENTS.md section), `tests/smoke.sh` (228). Payload: 8 agents (intake, spec-writer, builder, reviewer-code/security/ui/ux, approver), `.claude/skills/factory/SKILL.md` (260), `factory/bin/{job 718, gate 121, route 51, dashboard 160}`, `factory/dashboard.html`, `factory/checks.sh` (19-line placeholder that **exits 1**), `factory/config.json`.

**Skill and modes:** `SKILL.md` only selects the mode and sets rules; first instruction "Read INSTALL.md in full"; no argument means `upgrade` if `factory/VERSION` exists, else `init`; never `init` over an existing install. Rules: stay on the user's branch; never push or change labels without asking; learn the script's interface from `--help`; never hand-edit `config.json` (use `config set`); `checks.sh` is the gate and the most important file; commit by explicit path; a skipped, xfailed or not-run test is a failure. `init` has 9 steps (preflight, copy, gitignore + agents-md, write checks.sh, config set, tailor 5 agents, labels dry-run then `--yes`, verify, commit and hand over). The agent does judgment (choosing real commands from CI and AGENTS.md, tailoring prompts, asking the owner about costly or skipped tests); scripts do everything deterministic.

**`factory_setup.py`:** subcommands `preflight`, `copy`, `gitignore`, `agents-md [--migrate]`, `labels [--yes]`, `config get|set [--add]`, `detect`, `verify-checks [--break FILE]`, `upgrade-plan`, `upgrade-apply [--yes] [--mark-reviewed]`.
- *preflight:* origin exists and is GitHub, `gh auth`, viewer permission, `origin/<base>` after fetch, `claude >= 2.1.257`, python >= 3.10; refuses if payload files exist; warns on dirty tree.
- *manifest* `factory/.setup-manifest.json`: version, sha256 of each shipped file, a comment-stripped hash of exec scripts, and `reviewed` (payload hash a human last reviewed).
- *upgrade `classify`:* target missing -> `missing`/`new`; equal to new payload -> `current`; equal to pristine manifest hash -> `safe` (auto-overwritten, with `new`, `missing`); otherwise held as `adapted`, `modified` or `clash`; project-owned files (`checks.sh`, `config.json`) never overwritten; held files show a diff count and "comments only" when the code hash is unchanged, or `kept` if unchanged since last review; `removed-upstream` reported; `upgrade-apply` is a dry run unless `--yes`.
- *`verify-checks` ("sabotage"):* refuses on tracked changes; makes a detached worktree of HEAD, runs `checks.sh` twice cleanly and fails if output reports skipped/xfailed/deselected/ignored/pending tests; with `--break FILE` appends a garbage line to the file in a second throwaway worktree and requires a non-zero exit; warns "suspicious" if the failure took under 2 s and does not name the file; without `--break` prints a NOTE that the script was not shown able to fail.
- *`config set`:* parses the value as JSON else string, edits only the value's characters with a hand-written scanner to keep formatting, re-validates, writes a temp file and `os.replace`.
- *`detect`:* finds node/python/go/rust/make, CI `run:` lines, docs; reports linter/typecheck gaps and greps for skip/xfail patterns.

**The payload factory:** the session running `/factory run` becomes the orchestrator and spawns every agent in the background; reads GitHub issues labelled `factory`; intake decides ACCEPT / NEEDS-INFO / REJECT and rates risk and surfaces; `bin/route` maps risk and surfaces to reviewers and models; worktree `.worktrees/<id>` on branch `factory/<id>` from `origin/<base>`; spec-writer writes `spec.md`; builder implements, pushes, opens a draft PR ("Closes #n") and writes `build.md` starting `STATUS: READY|BLOCKED`; `bin/gate` runs the **main checkout's** `checks.sh` inside the worktree; on FAIL the builder gets the log and no reviewers run; routed reviewers run in parallel, any CHANGES verdict returns to the builder; approver writes `decision.md` APPROVE (then `job merge`) or ESCALATE (PR ready, comment, label `factory:needs-human`); limit `max_rounds` default 3. `bin/job` is the only writer of `job.json`, with a TRANSITIONS table whose `advance()` checks the evidence files for each move (e.g. build -> gate needs `build.md` READY, clean worktree, commits ahead, pushed branch, exactly one open PR). `bin/gate` fails if the branch modified or deleted any `protected_paths` file (`checks.sh`, `config.json`; additions allowed), and `gate --hook` is the builder's SubagentStop hook that re-runs the gate and exits 2 so the builder cannot stop on a red build. Issue text reaches agents only as quoted data; the `factory` label is the trust boundary.

**Templates:** each check starter installs deps then lint, typecheck, tests, build, with `set -euo pipefail`, no `|| true`, no `--fix`; test output is teed and grepped for skip counts so a skip fails the script.

**Origin (resolves the open item in research 01):** `NOTICE` says `payload/` derives from "software-factory-claude-code-v2" in `https://github.com/zazencodes/zazencodes-season-3` (ZazenCodes), path `src/software-factory-claude-code-v2`, commit `5fc7c983f44d623057ef65361f25cf23cab2abef`, GPLv3 (the earlier guess of a separate repo was wrong: it is a folder inside the season-3 repository).

**README vs code:** no serious divergence; minor: `agents-md --help` says "two ignore lines" but there are four; `ADAPTED` includes the project-owned files.

**Worth borrowing:** (1) manifest-based upgrade with `--mark-reviewed`; (2) checks that can fail (two clean worktree runs, one sabotaged run, fail on skipped tests); (3) protected gate (the check script comes from the main checkout, `protected_paths` diff, a Stop hook, a single-writer state script with an evidence-checked transition table).
**Weaknesses:** prompt-driven, much of the safety rests on agent compliance with `INSTALL.md`, needs `gh`/GitHub and a minimum Claude version; sabotage appends text to one file, so it proves some failure is detected, not that tests catch behavior regressions, and skip detection is output-regex; hash classification cannot merge, so any tailored file means a manual diff, config merge is manual, hand-written JSON scanner is extra risk.
**Not verified:** installer and smoke tests were not run; `payload/factory/bin/job` lines 512-718, reviewer prompts, `dashboard.html`, most of `tests/smoke.sh` not read in detail; upstream repo not opened; model names and the Claude version are unverified.

## 3. riquenandez/ts-factory

**Size:** 174 tracked files, ~17.6k lines (lockfiles and images excluded); single-commit shallow clone ("drop the upstream credit line"). `factory/` (12 ADW scripts + `adw_modules/`, prompts for 5 agents, `sssf.config.yaml`, `justfile`), `cookbooks/`, `references/`, `design/` (CONTRACTS, RATIONALE, KNOWN_ISSUES), `scripts/` (install, makeAdw, makeConfig), `apps/visualizer/` (Vue + Bun). Top-level `tests/` run the port against fake agents (fake claude, pi, copilot, exec) and compare snapshots; `.audit/*.tsv` is an append-only port log. Largest engine files: `tracer.ts` (342), `execute.ts` (338), `runtimes/claude.ts` (302).

**Relation to SSSF (confirmed by this repo's own files):** `.audit/bun-ts-port.tsv`, `design/RATIONALE.md` ("TypeScript port... Python original at tag `python-gold-final`") and `CONTRIBUTING.md` describe a Python-to-TypeScript port done in one day (2026-09-08) with a differential parity harness (exit code, stdout, sqlite dump, jsonl, git porcelain), mimicking Python quirks. The disler repo itself was not fetched by this helper (section 1 covers it).

**Skill and install:** same operator contract as SSSF (startup: read overview, list `Phases:` docstrings, print table, wait; "volunteered state is guessed state"; lazy cookbook routing; ten hard rules; "`writes:` is the boundary and `tools:` is only a capability list"). `install.ts` `stamp()` copies recursively, skips existing destinations unless `--force`; `makeAdw.ts` generates `adws/adw_<name>.ts` from fixed agent-to-output-type/gates mappings with a "TODO: replace this description" placeholder.

**Engine:** `Run.phase` (`runner.ts`) defaults to "fail", flips on clean return; `run.finish({accepted})` alone decides exit 0/1 (green phases with `accepted=false` exit 1); `signalDoor` kills live agent pids from the `processes` table on SIGTERM/SIGINT. Envelope base `{status, summary, artifacts[], notes_for_next_agent}` plus typed extensions (Plan, Build with `changed_files`/`commit_message`, Scout, Review with `approved`/`findings`/`blocking`, Document, Verify, Changes). Agents launch through `runtimes/{pi,claude,copilot,exec}.ts` with `Bun.spawn` and streamed JSONL (Claude: `claude -p --output-format stream-json --session-id|--resume ... --permission-mode dontAsk --strict-mcp-config`). `parseWithRetries`: up to 3 attempts in the same session; each failed attempt stored in `envelopes` with `valid=0`. Gate retries: `max(1, retries+1)` rounds with the "failed validation, re-emit ONLY your Report JSON" message; **default `retries` is 0, so a gate failure is fatal unless the ADW passes `retries`**.

**Gates:** `artifactsExist`, `filesNonEmpty`, `jsonParses`, `diffMatchesClaims` (**existence check only; does not compare to git diff**, so an agent that omits files or invents-and-creates files passes), `verdictConsistent` (logical only), `testsPass(cmd)` (shell, no cwd). `quality.ts` is a real subprocess runner (per-check timeout, `command.log`, `tool_call` event) but all four blocks ship as `echo PLACEHOLDER ...` exiting 0.

**Permissions:** snapshot/diff/`enforce`/`permitted` as in SSSF (defaults `protected_files`: `adws/adw_modules/`, `adws/adw_sssf_config/`, `adws/adw_*.ts`; builder `writes === null`, reviewer `[]`). Rollback: unlink untracked; `git checkout -- path` tracked; then `PermissionBreach`. Edge cases (some in `design/KNOWN_ISSUES.md`): **enforcement is skipped when parsing or gates fail first** (a breach plus bad JSON leaves the file on disk); same-count edits to already-dirty files are invisible; **committed changes are invisible (diff is against HEAD), so `git commit` inside an agent escapes**; no sandbox, outside-repo writes unseen; `git checkout` does not clean staged state or ignored files.

**Trace:** seven tables as in SSSF (`sessions`, `phases`, `events`, `envelopes`, `gate_results`, `processes`, `agent_sessions`), WAL; readers: `justfile` + `sqlite3`, Bun visualizer (`/api/sessions`, `/events`, `/envelopes`, `/gates`, `/agents/:agent/prompts`) on port 4601; the only UI write is the `archived` flag.

**README vs code:** largely accurate; `KNOWN_ISSUES.md` lists admitted bugs kept for snapshot parity (`enforce` skipped on parse/gate failure; `tools: []` gives pi its defaults; `quality.test` recorded as operation "build"; quality `tool_call` payload has no `ok`, so a failed quality block looks fine in the UI; `parent_id` always `""`; `--adw-id` does not hydrate `previous`; inconsistent cwd handling).

**Worth borrowing:** write-boundary enforcement (snapshot, diff, rollback, per-agent `writes` + global `protected_files`); the typed-envelope triad with in-session JSON-fix retry and per-check gate reports; a thin operator skill with a "do not volunteer state" rule and `finish(accepted)`.
**Weaknesses:** weak verification (existence-only claim gate, passing placeholder quality commands, zero default gate retries); detect-and-undo enforcement with the holes above, runs on the live branch; Python-isms and known bugs kept on purpose for parity.
**Not verified:** nothing run; Vue components, every cookbook line, `pi.ts`/`copilot.ts`/`exec.ts` beyond CLI flags, and prompt contents not read in depth.

## 4. PaddyMc/software-factory

**Size:** ~18.1k Python lines including tests and bench fixtures; version 0.1.0; README says it was "extracted from the Cleartree project's factory". Biggest: `cli.py` (1312), `web/views.py` (1231), `bench/run.py` (728), `pipeline.py` (726), `web/server.py` (455), `agents.py` (394). Small core: `gates.py` 193, `contracts.py` 237, `db.py` 252, `sandbox.py` 126, `tools.py` 152, `flows.py` 140, `stack.py` 166, `verification.py` 44. ~20 test files (`test_pipeline.py` 1834 lines with `tests/fake_model.py`). Dependencies: `pyyaml`, `langchain`, `langgraph`, `langchain-anthropic`, `-openai`, `-openrouter`. Docs: `docs/architecture.md` (656), `docs/reference.md` (471), `NEXT.md` (184), `docs/plans/*`, `docs/sessions/*`.

**Task contract (`contracts.py`):** a plan is a markdown file with a fenced yaml list; each item has exactly 8 keys `id, goal, spec_refs, depends_on, non_goals, acceptance, verification, risk`; missing or extra keys rejected. Rules: non-empty strings; `ID_RE` `^[a-z0-9]+(-[a-z0-9]+)*-t\d{2}[a-z]?$`; `risk` in low/medium/high; `acceptance` non-empty. `validate_tasks` adds duplicate ids, unknown dependencies and cycles (DFS across all plans), a verification-command linter (`check_command` rejects prose prefixes like "Run"/"Check", `pytest -k` without an expression, `cargo test --exact` without a name), a placeholder ban (`TODO|TBD|FIXME|XXX|<UPPER>`); `validate-plan` also warns when a verification command matches `DENIED_COMMANDS` (`terraform apply`, `sudo`, `gh`, `git push`, `factory`). **Plans never hold status** (status lives in the DB); `contract_hash` (sha256) exists. Dependency semantics: satisfied if `merged`, or `pr_open` with a `candidate_sha`; in the second case the dependent is **stacked** (worktree starts from the dependency's candidate, PR targets `factory/<dep>`), several open dependencies are merged into one worktree, `restack` rebases as dependencies merge, a rebase failure becomes `conflict`. Contracts do not fence which files the builder may touch.

**State (`db.py`, SQLite WAL):** `tasks` (id, plan, contract JSON, status, branch, base_ref, base_sha, candidate_sha, pr_url, attempts, note, progress, updated_at + pid, heartbeat, cost, stacked_on, ...) and `runs` (id, task_id, role, attempt, model, outcome, sha, report, steps, tokens, cost, transcript, flow, prompt_version, ...). `STATUSES`: queued, planning, building, reviewing, verifying, pr_open, conflict, ci_failed, changes_requested, merged, failed, abandoned. **Transitions are not enforced by a table**: scattered `db.update(status=...)` calls validate only the status name. The pipeline is a LangGraph `StateGraph` (entry plan / resolve / rework -> build -> review and gates in flow order -> verify -> pr); CHANGES or a gate failure loops back to build up to `max_attempts` (default 3); two identical gate-failure signatures in a row set `stuck` and end the task `failed`; `max_cost` aborts. `flows.py` lets config reshape the flow (`[plan]? build+ (review|gates)* [verify]?`, at most one gates step, one auto-inserted if missing, so gates always decide).

**Agents:** prompts `factory/prompts/{planner,builder,reviewer,verifier}.md` (16-26 lines each, front-matter `model`, `max_steps`; defaults GLM for planner/reviewer, DeepSeek for builder/verifier via OpenRouter; per-repo override in `.factory/agents/`; `prompt_version` hashes prompt plus repo guidance). Planner: read-only tools, markdown plan (Files, Steps, Tests, Acceptance mapping, Risks). Builder: read tools plus `write_file`/`edit_file` (anywhere in the worktree except `.git`) and a sandboxed `run`; ends `RESULT: DONE|BLOCKED` (not seen to be branched on); the factory commits for it. Reviewer: read tools plus `git_diff base..HEAD`; ends `VERDICT: APPROVE|CHANGES`, **`parse_verdict` takes the last `^VERDICT:` line and treats anything else as CHANGES (fail-safe)**. Verifier: runs after gates pass, only writes the PR summary, cannot override gates. `tools.PathGuard`: writes only in the worktree, `.git` refused, refusals counted per run; `run` refuses `DENIED_COMMANDS`.

**Gates (`gates.run_gates`), on the exact candidate sha, in order:** `clean` (HEAD equals candidate, worktree clean), `diff`, `conflict_markers` (added `<<<<<<<` etc.), `plan_untouched`, `session_log` (config), `e2e_written` (config; detects `#[test]`/`def test_*` in the diff under `e2e.dir`), `verification` (runs each contract command in the sandbox; **exit 5 from pytest or zero tests selected counts as INCONCLUSIVE = failure**), `unit_tests`, `e2e_tests` (config). `passed()` is true if none is False; skipped gates are None. The PR opens only after this (`git push --force-with-lease`, `gh pr create` on the host, outside the sandbox). The default flow runs the reviewer **before** the gates (a documented limitation).

**Sandbox (`sandbox.py`):** `bwrap --die-with-parent --unshare-all [--share-net only if network] --ro-bind / / --dev /dev --proc /proc --tmpfs /tmp --tmpfs /run --tmpfs $HOME`, configured rw/ro binds and hidden paths, read-write bind of the worktree with `--clearenv` (only HOME, PATH, LANG, TERM and configured env); the factory DB is invisible inside, so agents cannot change task state; worktrees in `$FACTORY_HOME/worktrees/<task>` on `factory/<task>`; secrets (OpenRouter key, GitHub token) stay in the host process. Agents cannot commit, push or use `gh`/`factory`. Limits: the denylist is regex-based and bypassable in principle (bwrap is the real isolation); `write_file`/`edit_file` run in the host process under `PathGuard`; Linux only.

**`factory init` (`scaffold.py`):** writes `.factory/config.yaml` (name from directory, `session_log: docs/sessions`, guessed `unit_tests`), copies skills `plan-workstream`, `review-task`, `factory-ops` into `.claude/skills/` (relative symlinks under `.agents/skills/` for Codex), `docs/sessions/README.md`, a starter `docs/plans/example.md`, and an AGENTS.md section between `<!-- factory:begin -->` and `<!-- factory:end -->`; idempotent, `--force` replaces only the marker region.

**README vs code:** no TODO/NotImplemented markers in `factory/`; claims "agents never push, merge or see secrets" and "a PR opens only when every deterministic check passes" are consistent with the code read. Unbuilt (docs): test-first step (`docs/plans/strict-flow.md`) and `e2e_fails_without_change` gate, a wiki/knowledge crew, steering a running agent, a shared board (two boards can run the same task), reviewer before gates, restacked PRs not re-gated, builder re-explores what the planner read.

**Compared with a harness where a planner agent writes the plan, the owner approves, an executor implements and a review closes the task - borrow:** (1) machine-validated contract (8 keys, id regex, cycle check, command linter, placeholder ban, status outside the plan); (2) deterministic gates decide merge-readiness and the model reviewer cannot override them, "zero tests selected = inconclusive", plan-untouched check, stuck detector; (3) fail-safe verdict parsing, a prompt version, cost and transcript per run, and `factory bench` replaying fixed cases against hidden tests.
**Weaknesses:** the human approves only at the PR (no pre-implementation plan approval; the planner agent writes a per-task implementation plan, not the contract); the builder writes the tests that judge it; ~60% of the code is UI/bench/stats/scheduler around a thin core; Linux-only sandbox, local SQLite, OpenRouter-hardwired models, regex denylists plus host-side file tools.
**Not verified:** nothing run; `pipeline.py` read selectively (plan/resolve/rework/verify node bodies skimmed); `config.py`, `reviews.py`, `ci.py`, `merges.py`, `scheduler.py`, `web/`, `bench/` not read in detail; defaults like `max_attempts` come from prompts and reading, not from running; the claim that `git push`/`gh` never receive agent-controlled arguments was not checked.

## 5. juan-campuzano/minifactory

**Size:** single commit dated 2026-11-05, package `0.0.2a4` (alpha); source ~6.3k lines (`core` 745, top-level modules 772, `cli/` 1762, `plugins/builtin/steps` 1626, `providers` 595, `routing` 278, `support` 394, `tools` 158) against ~4.9k lines of tests; 8 packaged templates, 5 stack profiles, 5 role YAMLs, an Astro docs site; 225 tracked files; `AGENTS.md` is the single agent file.

**Workflow schema (`core/workflow.py`, pydantic, `extra="forbid"`):** `WorkflowSpec` = `schema_version: 1`, `name`, optional `route`, `vars`, `source`, `executor` (default `local`), `runner` (default `host`), `providers` (only `scm`, `llm`, `secrets`), `llms` (role-to-LLM overrides), `steps`. `StepSpec` = `id`, `use`, `with`, `when`, `on_fail` (`fail|discard|continue`), `blocking` (default true). `route` (`description`, `not_for`, `examples`, `needs`, `intake`, `delivery: choose|fixed`) makes a workflow reachable from `ask`. Templating `${...}` over `job`, `steps` (`.status/.message/.outputs`), `vars`, `env`; `when` uses a tiny expression language (`core/expr.py`: names, attributes, literals, lists, comparisons, `in`, `and/or/not`; no calls, indexing or arithmetic). `validate_spec` runs before anything: plugin names exist; each step's `needs` present; no duplicate step ids; `with` validated against the step's `Params` (templated values skipped, missing keys still errors); `when` parses; any `steps.X` reference points to an earlier step. No loops by design ("if you need that, write a step in Python"): retry loops live in step code (`agent.repair_build`, `agent.ui_loop`).
