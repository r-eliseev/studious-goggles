## 1. disler/super-simple-software-factory (SSSF)

**Size:** ~13.9k lines, ~100 files, all under `.claude/skills/sssf/`; Python ~3.6k LOC, TS/Vue ~5.4k (visualizer app), Markdown ~2.2k. No tests directory anywhere. `scripts/`: `install.py`, `make_adw.py`, `make_config.py`; `templates/adws/` has 13 ADW scripts and `adw_modules/` (agents, runner, permissions, gates, quality, tracer, data_types, agent_pi, git_helper, changes, session, console, prompts, utils, agent_cc); prompts for planner, builder, reviewer, scout, documenter.

**Skill:** `SKILL.md` is a behavior contract for the operator session: reads an overview, lists each ADW's `Phases:` docstring, prints a table, waits; forbids volunteering state or querying the DB (a previous orchestrator invented tables that do not exist); never does ADW work itself; lazy-loads one cookbook per request type. Ten hard rules, among them: validate agents before running; typed envelopes with a "synced triad" (type in `data_types.py`, JSON example in `user.md`, `output_type=` at the call site); gates check claims; at most 4 params per function; one agent, one prompt; known commands are code, not agents; `writes:` and `protected_files` are enforced; every ADW ends in `run.finish(accepted=)`.

**Install:** `install.py` is plain `shutil.copy2`; skips existing destinations unless `--force`; appends missing runtime entries to `.gitignore`. No merge, so template changes never propagate without `--force`.

**Engine:** an ADW is a Python script: `REQUIRED_AGENTS`, `agents.load_config` + `agents.validate`, `session.ensure` -> `Run`; each phase is `with run.phase(PhaseParams(name, kind, owner, description, retries))` (`kind`: engineer, agent, code). `Run.phase` (`runner.py`) defaults to fail and flips to success only on clean exit; an exception records the error, fails the session and re-raises. A validator rejects empty phase descriptions and ones that restate the name. Control flow is plain Python loops (`adw_simple_sdlc`: plan, commit plan, build, up to 3 test/fix rounds, up to 2 review/revise rounds, retest, commit, changes, document; ends in `run.finish(accepted=verified)`). Agents run as `pi -p --mode json ...` via `subprocess.Popen` (`agent_pi.py`), stdout tailed as JSONL; `validate()` calls `pi --list-models`. Envelope parsing: `_extract_json` (first fenced block starting `{`, else first `{` to last `}`) validated against a pydantic `output_type` (`EnvelopeBase`: status, summary, artifacts, notes_for_next_agent); on failure `_parse_with_retries` re-prompts the same pi session up to `JSON_FIX_ATTEMPTS=2`; gate violations use the same route bounded by `phase.params.retries`, then `GateFailure`.

**Gates (actual checks):** `artifacts_exist`; `files_non_empty`; `json_parses`; `diff_matches_claims` (only checks that each path in `changed_files` **exists**, not that it changed); `verdict_consistent` (review `approved` vs `blocking` list and unmet findings); `tests_pass(command)` (runs a shell command with `shell=True`). `quality.py` blocks (`test`, `lint`, `typecheck`, `build`) all ship as `_placeholder` echoes that exit 0, so a fresh install's tests are vacuous (the README admits it).

**Permissions (`permissions.py`):** detective, by diffing the working tree: `snapshot` fingerprints `git diff HEAD --numstat` plus untracked files; `agents.execute` snapshots before the first send and calls `enforce` after retries and gates; a reverted path counts as changed. `permitted()` order: `data_dir/` always allowed; agent `writes` match allows (and unlocks protected files); `protected_files` match denies; otherwise allowed only if `writes is None` (`[]` = read-only). Rollback: untracked file unlinked, tracked file `git checkout -- path`, a path already dirty before the call is left alone (reported if the agent reverted it). Then `PermissionBreach` kills the phase (never retried). Limits: writes outside the repo or to gitignored paths are invisible; edits to an already-dirty file are caught only if numstat counts change; the agent's bash is unsandboxed.

**State (SQLite via `tracer.py`, WAL):** tables `sessions`, `phases` (status default `'fail'`), `events`, `envelopes`, `gate_results`, `processes`, `agent_sessions`; on disk `adws/adw_data/sessions/<adw_id>/` (`agent_map.json`, `context_handoff/`, per-agent prompts, raw output, envelope, pi sessions). A rejoined `--adw-id` resumes agent context only if the model is unchanged. The visualizer polls the DB at ~500 ms.

**README vs code:** README is mostly honest (`claude_code` is a 15-line stub that raises; quality placeholders). `SKILL.md` says the visualizer ships "in a later pass", but it exists. Config names models/providers (`kimi-k3`, `gpt-5.6-terra`, `gemini-3.6-flash`) the helper could not verify. Zero tests for the harness itself.

**Worth borrowing:** (1) post-hoc permission enforcement by tree diff with per-role `writes` (planner only `docs/`+`tasks/`; executor not `scripts/` or `.github/`); (2) typed envelopes with self-consistency gates and corrections fed back into the same session, bounded; (3) acceptance separated from phase success (`run.finish(accepted=)`), known commands as code, failures wrapped as envelopes, commit the plan before code.
**Weaknesses:** enforcement is detective only and the existence-only claim gate proves little; depends on an external CLI and model JSON discipline, and task state lives in SQLite and scripts, not in reviewable repo files; install is copy-and-skip with no upgrade path, `tests_pass` uses `shell=True`, default test phase passes vacuously.
**Not verified:** no runtime behavior (pi JSON format, SQLite concurrency, rollback correctness, visualizer); `session.py`, most of `data_types.py`, cookbooks, other ADW scripts and the visualizer source were not read.

## 2. dwightfowler-tema/factory-setup

**Size:** ~5.2k lines, 36 files (GPLv3 text included), `VERSION` 0.4.0; shallow clone has one commit. `SKILL.md` (41 lines), `INSTALL.md` (186), `scripts/factory_setup.py` (877, stdlib only), `payload/` (the factory), `templates/` (checks for go, make, node, python, python-uv, rust, and an AGENTS.md section), `tests/smoke.sh` (228). Payload: 8 agents (intake, spec-writer, builder, reviewer-code/security/ui/ux, approver), `.claude/skills/factory/SKILL.md` (260), `factory/bin/{job 718, gate 121, route 51, dashboard 160}`, `factory/dashboard.html`, `factory/checks.sh` (19-line placeholder that **exits 1**), `factory/config.json`.

**Skill and modes:** `SKILL.md` only selects the mode and sets rules; first instruction "Read INSTALL.md in full"; no argument means `upgrade` if `factory/VERSION` exists, else `init`; never `init` over an existing install. Rules: stay on the user's branch; never push or change labels without asking; learn the script's interface from `--help`; never hand-edit `config.json` (use `config set`); `checks.sh` is the gate and the most important file; commit by explicit path; a skipped, xfailed or not-run test is a failure. `init` has 9 steps (preflight, copy, gitignore + agents-md, write checks.sh, config set, tailor 5 agents, labels dry-run then `--yes`, verify, commit and hand over). The agent does judgment (choosing real commands from CI and AGENTS.md, tailoring prompts, asking the owner about costly or skipped tests); scripts do everything deterministic.

**`factory_setup.py`:** subcommands `preflight`, `copy`, `gitignore`, `agents-md [--migrate]`, `labels [--yes]`, `config get|set [--add]`, `detect`, `verify-checks [--break FILE]`, `upgrade-plan`, `upgrade-apply [--yes] [--mark-reviewed]`.
- *preflight:* origin exists and is GitHub, `gh auth`, viewer permission, `origin/<base>` after fetch, `claude >= 2.1.257`, python >= 3.10; refuses if payload files exist; warns on dirty tree.
- *manifest* `factory/.setup-manifest.json`: version, sha256 of each shipped file, a comment-stripped hash of exec scripts, and `reviewed` (payload hash a human last reviewed).
- *upgrade `classify`:* target missing -> `missing`/`new`; equal to new payload -> `current`; equal to pristine manifest hash -> `safe` (auto-overwritten, with `new`, `missing`); otherwise held as `adapted`, `modified` or `clash`; project-owned files (`checks.sh`, `config.json`) never overwritten; held files show a diff count and "comments only" when the code hash is unchanged, or `kept` if unchanged since last review; `removed-upstream` reported; `upgrade-apply` is a dry run unless `--yes`.
- *`verify-checks` ("sabotage"):* refuses on tracked changes; makes a detached worktree of HEAD, runs `checks.sh` twice cleanly and fails if output reports skipped/xfailed/deselected/ignored/pending tests; with `--break FILE` appends a garbage line to the file in a second throwaway worktree and requires a non-zero exit; warns "suspicious" if the failure took under 2 s and does not name the file; without `--break` prints a NOTE that the script was not shown able to fail.
- *`config set`:* parses the value as JSON else string, edits only the value's characters with a hand-written scanner to keep formatting, re-validates, writes a temp file and `os.replace`.
- *`detect`:* finds node/python/go/rust/make, CI `run:` lines, docs; reports linter/typecheck gaps and greps for skip/xfail patterns.

**The payload factory:** the session running `/factory run` becomes the orchestrator and spawns every agent in the background; reads GitHub issues labelled `factory`; intake decides ACCEPT / NEEDS-INFO / REJECT and rates risk and surfaces; `bin/route` maps risk and surfaces to reviewers and models; worktree `.worktrees/<id>` on branch `factory/<id>` from `origin/<base>`; spec-writer writes `spec.md`; builder implements, pushes, opens a draft PR ("Closes #n") and writes `build.md` starting `STATUS: READY|BLOCKED`; `bin/gate` runs the **main checkout's** `checks.sh` inside the worktree; on FAIL the builder gets the log and no reviewers run; routed reviewers run in parallel, any CHANGES verdict returns to the builder; approver writes `decision.md` APPROVE (then `job merge`) or ESCALATE (PR ready, comment, label `factory:needs-human`); limit `max_rounds` default 3. `bin/job` is the only writer of `job.json`, with a TRANSITIONS table whose `advance()` checks the evidence files for each move (e.g. build -> gate needs `build.md` READY, clean worktree, commits ahead, pushed branch, exactly one open PR). `bin/gate` fails if the branch modified or deleted any `protected_paths` file (`checks.sh`, `config.json`; additions allowed), and `gate --hook` is the builder's SubagentStop hook that re-runs the gate and exits 2 so the builder cannot stop on a red build. Issue text reaches agents only as quoted data; the `factory` label is the trust boundary.

**Templates:** each check starter installs deps then lint, typecheck, tests, build, with `set -euo pipefail`, no `|| true`, no `--fix`; test output is teed and grepped for skip counts so a skip fails the script.

**Origin (resolves the open item in research 01):** `NOTICE` says `payload/` derives from "software-factory-claude-code-v2" in `https://github.com/zazencodes/zazencodes-season-3` (ZazenCodes), path `src/software-factory-claude-code-v2`, commit `5fc7c983f44d623057ef65361f25cf23cab2abef`, GPLv3 (the earlier guess of a separate repo was wrong: it is a folder inside the season-3 repository).

**README vs code:** no serious divergence; minor: `agents-md --help` says "two ignore lines" but there are four; `ADAPTED` includes the project-owned files.

**Worth borrowing:** (1) manifest-based upgrade with `--mark-reviewed`; (2) checks that can fail (two clean worktree runs, one sabotaged run, fail on skipped tests); (3) protected gate (the check script comes from the main checkout, `protected_paths` diff, a Stop hook, a single-writer state script with an evidence-checked transition table).
**Weaknesses:** prompt-driven, much of the safety rests on agent compliance with `INSTALL.md`, needs `gh`/GitHub and a minimum Claude version; sabotage appends text to one file, so it proves some failure is detected, not that tests catch behavior regressions, and skip detection is output-regex; hash classification cannot merge, so any tailored file means a manual diff, config merge is manual, hand-written JSON scanner is extra risk.
**Not verified:** installer and smoke tests were not run; `payload/factory/bin/job` lines 512-718, reviewer prompts, `dashboard.html`, most of `tests/smoke.sh` not read in detail; upstream repo not opened; model names and the Claude version are unverified.
