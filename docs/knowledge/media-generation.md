# Video and audio generation: providers and playback

Research of task 166, 2026-11-06. Sources are the providers' public APIs and documentation on that date; everything not verified by a live paid request is marked. Decisions: ADR 0027.

## OpenRouter: video

- Catalog: `GET https://openrouter.ai/api/v1/videos/models`, without a key (checked with `curl` on 2026-11-06): 31 models (Google Veo 3.1 / 3.1 Fast / 3.1 Lite, Gemini Omni 1.1/1.2 Flash, Kling v3.0 Pro/Std and O1, Seedance 1.5 Pro / 2.0 / 2.0 Fast / 2.0 Mini / 2.5, Wan 2.6 / 2.7 / 3.0 / 3.0 Prime, Hailuo 2.3 / 3 / 3 Max, Runway Gen-4.5 and Aleph 2, FLUX 3 Video, Grok Imagine Video, HeyGen and others).
- Model fields: `id`, `name`, `description`, `supported_durations` (whole seconds), `supported_resolutions` (`360p`…`4K`), `supported_aspect_ratios`, `supported_sizes` (`WxH`), `supported_frame_images` (`first_frame`, `last_frame`), `generate_audio` (`true`/`false`/`null`), `seed` (`true`/`false`/`null`), `pricing_skus` (a string → numeric-string dictionary), `allowed_passthrough_parameters`. Some models (`flux-video-edit`, `flux-video-upscale`, `aleph-2`, `avatar-iv`) have no durations: they are editing/upscaling/avatar, not text-to-video generation.
- `pricing_skus` units (by key names, 2026-11-06): `duration_seconds[_with_audio|_without_audio][_<resolution>]` — USD per second; `cents_per_second_output[_<resolution>]`, `cents_per_video_output_second_<resolution>` — cents per second; `minimum_cents_per_generation` — the minimum per run; `cents_per_image_input` — per input picture; `video_tokens[_without_audio|_4k]` — per "video token", the conversion to seconds is unknown; `cents_per_megapixel_second_*` — for upscaling. An unknown key = the price is unknown.
- Generation is asynchronous (the OpenRouter documentation "Video Generation", 2026-11-06): `POST /api/v1/videos` with `model`, `prompt`, `duration`, `resolution`, `aspect_ratio` or `size`, `frame_images` (`[{type, image_url, frame_type: first_frame|last_frame}]`), `input_references`, `generate_audio` (`true` by default where supported), `seed` (not guaranteed), `callback_url`, `provider`. A 202 response: `id`, `polling_url`, `status: pending`.
- Polling: `GET /api/v1/videos/{id}` → `status` (`pending`, `in_progress`, `completed`, `failed`; webhooks also have `cancelled`, `expired`), `unsigned_urls`, `urls` (signed, with `expires_at`, only if OpenRouter keeps a copy), `usage.cost`, `usage.is_byok`, `error`. The documentation advises polling about every 30 s; generation takes from 30 s to several minutes.
- The file: `GET /api/v1/videos/{id}/content?index=0` with `Authorization`. The format is not given in the documentation; the example saves `video.mp4`. The retention time is unknown.
- The documentation has no cancellation. Cancellation in the app can only stop waiting; the provider will probably charge anyway — unknown.
- Not verified by a live request: the actual response fields, `usage.cost` in USD, the file type, file sizes.

## OpenRouter: audio

- In the general catalog (`GET /api/v1/models`, 2026-11-06) audio output is given by: `google/lyria-3-pro-preview` (description: "$0.08 per song"), `google/lyria-3-clip-preview` ("30 second duration clips are priced at $0.04 per clip"), `openai/gpt-audio`, `openai/gpt-audio-mini` (speech). There is no separate `/audio/models` catalog (404). There are no sound effect models. Models with `speech` output (TTS) — see below.
- Speech models (`speech`, 38 as of 2026-11-07: ElevenLabs, OpenAI, Mistral, HeyGen, Fish Audio and others) are a separate API `POST /api/v1/audio/speech`, compatible with OpenAI Audio Speech: `model` and `input` are required, `voice`, `response_format` (`mp3`, `pcm`); the response is audio bytes with a `Content-Type` (`audio/mpeg`, `audio/pcm`); without `voice` the request goes only to providers with a default voice. The price is per character of input text (`pricing.prompt`). The list: `GET /api/v1/models?output_modalities=speech`. Source: the OpenRouter documentation "Text-to-speech" and the "Audio APIs" announcement (2026-11-07); not verified by a live request.
- Audio output (`audio`) goes through `POST /api/v1/chat/completions` with `modalities: ["text","audio"]`, `audio: {voice, format}` and a mandatory `stream: true`; chunks come in `delta.audio.data` (base64) and `delta.audio.transcript` (the "Audio" documentation, 2026-11-06). The LiveCheck scenario is implemented, but the parameters, format, duration, price and `usage` of Lyria remain unverified until the owner's live request: after setting `IMAGEGEN_LIVE_OPENROUTER_KEY`, run `dotnet run --project ImageGen/ImageGen.LiveCheck -- --budget-usd 0.2 --only music`.

## fal.ai and Together (not chosen, for reference)

- fal: the public catalog `GET https://api.fal.ai/v1/models?category=text-to-audio|text-to-video|image-to-video` (without a key) and each model's schema `?endpoint_id=…&expand=openapi-3.0`. Models have different fields (for example, ElevenLabs Sound Effects v3 — `text`, `duration_seconds` 0.5–30, `loop`; MiniMax Music 2.6 — `prompt`, `lyrics`; Kling v3 — `duration` as a string); the result is `audio`/`video` with `url`, `content_type`, `file_size`. Prices: `GET /v1/models/pricing` only with a key (401 without one).
- Together: video through the SDK `client.videos.create/retrieve`, statuses `queued`…`cancelled`, the result `outputs.video_url` (the link expires), `outputs.cost`; no audio generation (the "Videos overview" documentation, 2026-11-06).

## Playback

- MAUI: `CommunityToolkit.Maui.MediaElement` 10.0.0 (MIT, published 2026-06-02), targets `net10.0`, `-android36.0` (AndroidX Media3 ExoPlayer), `-ios26.0`, `-maccatalyst26.0`, `-windows10.0.19041`; requires `Microsoft.Maui.Controls` ≥ 10.0.60 (the project has 10.0.110).
- Avalonia: no built-in player. `LibVLCSharp.Avalonia` 3.10.2 (LGPL-2.1-or-later, 2026-10-13) depends on `Avalonia` ≥ 11.3.13 and is built for `net8.0`/`netstandard2.0`; `VideoView` compiles with Avalonia 12.1.4 (probe 206). A console LibVLC on Ubuntu 24.04 played a two-second MP4 with `--vout=dummy --aout=dummy`, got `Playing` and `EndReached`, length 2000 ms. Linux needs the system `libvlc5` (provides `libvlc.so.5`) and `vlc-plugin-base` (includes the MP4 demux plugin); without `libvlc5` the native LibVLC does not load. Removing the system packages for a separate negative run was not done. Windows `VideoLAN.LibVLC.Windows` 3.0.24 in a `win-x64` publish took 313,798,561 bytes under `libvlc/`, of which 111,588,790 bytes are the `win-x64` folder; the package also publishes win-x86 and win-arm64. Android `VideoLAN.LibVLC.Android` 3.6.5 built into an APK of 80,002,206 bytes, 19,400,423 bytes more than the Android head built without LibVLC (60,601,783 bytes). The build gave XA0141: `libvlc.so` and `libc++_shared.so` from the package for arm64 and x86_64 lack the 16 KB page alignment Android 16 requires from native libraries. Playback on an Android device and on Windows/macOS was not checked; the 16 KB warning should be removed before an Android release.

## OpenRouter: embeddings (live check of 2026-11-07)

`POST /api/v1/embeddings` with `baai/bge-m3`: HTTP 200, `model` in the response is the name at the chosen provider (`BAAI/bge-m3` at DeepInfra, `parasail-bge-m3` at Parasail in the owner's log of the same day), a `provider` field; `data[].embedding` — 1024 numbers, `data[].index` is present; `usage.cost` — USD (1.6e-07 for 16 tokens).
