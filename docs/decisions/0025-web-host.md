## Контекст

Приложению нужна Web-оболочка с API и браузерным интерфейсом. Хост должен повторно использовать Core и Data, не добавляя ASP.NET Core-зависимости в ядро. Первым этапом необходимо проверить запуск, миграции и восстановление прерванных генераций.

## Решение

Использовать ASP.NET Core minimal API в отдельном `ImageGen.Web` на `net10.0` с ASP.NET Core shared framework и ссылками на Core/Data. Интеграционные тесты размещать в `ImageGen.Web.Tests` с `Microsoft.AspNetCore.Mvc.Testing` 10.0.14 (MIT). Папку данных выбирать через `IMAGEGEN_DATA_DIR`, по умолчанию `/data`. Инициализацию БД и восстановление выполнять hosted service до обработки запросов. Вход реализовать cookie-сессией и antiforgery; поток событий — SSE с отдельной ограниченной подпиской каждому клиенту.

## Альтернативы

- ASP.NET Core-типы в Core: нарушает границу слоёв.
- Общий канал событий на всех клиентов: подписчики будут забирать события друг у друга.
- Новая серверная бизнес-логика: дублирует правила Core и повышает риск различий.

## Последствия

Web-хост остаётся отдельной оболочкой. Тестовая фабрика позволяет проверять реальный HTTP pipeline без запуска внешнего сервера. Для локального запуска требуется непустой `IMAGEGEN_WEB_PASSWORD`; постоянная папка данных должна сохранять БД, секреты и Data Protection key ring.
