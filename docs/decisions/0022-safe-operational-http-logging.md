# 0022. Безопасное и ограниченное HTTP-логирование

Статус: предложено
Дата: 2026-10-30

## Контекст
HTTP logging handler находится перед парсерами provider response. Без ограничения он предварительно буферизует весь request и response независимо от Content-Length. Операционные записи также могут сохранять текст исключения провайдера, хотя тела и заголовки содержат пользовательские данные и секреты. ADR 0010 определяет Serilog sink и уровни, но не разделяет операционные метаданные и подробности исключения.

## Решение
На Information/Warning/Error писать только безопасные структурированные операционные метаданные: метод, путь без query, статус, длительность и известный размер либо неизвестный. Не прикладывать exception object/message и не читать body на Information. Подробности исключений и отредактированные тела оставлять для Debug. Debug/trace используют общий request/response лимит и не записывают частичный body при превышении. Проверки ключа и запросы с флагом `SkipResponseBody` не читают response body ради logging. Заголовки остаются вне журналов.

## Альтернативы
- Читать все тела ради точного размера и последующего повторного чтения: отклонено, поскольку это позволяет недоверенным ответам исчерпывать память.
- Обрезать и записывать начало oversized body: отклонено, поскольку частичный текст может содержать секреты и затрудняет повтор trace.

## Последствия
Обычная эксплуатационная диагностика сохраняет method/path/status/duration и объявленный размер. Для тел и исключений требуется Debug. Debug/trace ограничены общими provider response limits и отдельным request body limit. Это правило применяется здесь к provider HTTP transport и не заявляет аудит всех существующих предупреждений приложения.
