# 0008. Хранение ключей в десктопе Avalonia

Статус: принято
Допустимые статусы: предложено, принято, заменено на NNNN, отклонено
Дата: 2026-10-28

Дополняет ADR 0006 (Avalonia, пункт 4: ключи в системных хранилищах, без них в памяти). Задача 040.

## Контекст
Avalonia не имеет встроенного защищённого хранилища (в MAUI это `SecureStorage`). Нужно три реализации `ISecretStore` для Linux, Windows и macOS, и запасной вариант: ключ только в памяти процесса, если системного хранилища нет.

Проверено пробным кодом (`poc/backlog/040-avalonia-secret-store/`) на Linux 2026-10-28, gnome-keyring 46 в изолированной сессии D-Bus:
- `org.freedesktop.secrets` (Secret Service) поднимается D-Bus-активацией; клиент на Tmds.DBus 0.95.1 (MIT) создаёт, ищет, читает и удаляет секрет через коллекцию `session` (проверено: `read matches=True`, после удаления пусто).
- Коллекция `default` (алиас `login`) в контейнере не создаётся: демон запрашивает пароль через `org.gnome.keyring.SystemPrompter`, а для него нужен дисплей. На настоящем рабочем столе коллекция уже есть, но так проверить не удалось. Если `ReadAlias("default")` возвращает `/`, считаем Secret Service недоступным.
- Коллекции в состоянии «заблокирована» или запрос, требующий промпта (`prompt != /`), в проверке не используем: это недоступно без интерфейса.

## Решение
1. **Linux — Secret Service** через D-Bus, библиотека `Tmds.DBus` 0.95.1 (MIT, опубликована 2026-09-04; версия 0.95.2 вышла 2026-10-27, её не берём, пока не пройдут две недели). Коллекция — алиас `default`. Доступность: подключение к сессии, `OpenSession("plain")`, `ReadAlias("default")` не равен `/`, запись без промпта. Иначе ключ в памяти.
2. **Windows — DPAPI** (`System.Security.Cryptography.ProtectedData` 10.0.12, MIT, `DataProtectionScope.CurrentUser`). Файл `secrets/<имя>.bin` в папке данных (`DesktopAppPaths`), в файле только зашифрованные байты. Имя файла проверяется: только латинские буквы, цифры, `_`, `-`, `.`.
3. **macOS — Keychain** через утилиту `/usr/bin/security`: запись `add-generic-password -U` с паролем в hex (`-X`), переданным через stdin интерактивного режима `security -i`, чтобы ключ не попал в аргументы процесса; чтение `find-generic-password -w`. **Не проверено** (нет macOS-машины, см. задачу 040).
4. **Запасной вариант — память процесса.** `DesktopSecretStore` выбирает бэкенд при первой проверке доступности (`IsPersistentAsync`, результат кешируется). Если бэкенда нет или он недоступен, значения живут в памяти до закрытия приложения.
5. **Интерфейс для страницы ключа.** В Presentation добавляется `ISecretPersistence` с `Task<bool> IsPersistentAsync(CancellationToken)`. Асинхронный метод вместо свойства из плана: проверка Secret Service — это D-Bus-вызов, его нельзя делать в конструкторе или на UI-потоке. MAUI реализует `true` (SecureStorage есть всегда).

Открытым текстом ключ на диск не пишется: ни в файлы DPAPI, ни в журнал, ни в аргументы процессов (см. п. 3).

## Альтернативы
- **libsecret через P/Invoke:** одна библиотека C, но нужен glib и собственная обвязка указателей; для проверки получили бы ту же службу, только сложнее.
- **Вызывать `secret-tool` как процесс:** не нужна библиотека, но на машине без `libsecret-tools` ничего не работает, и пароль проходит через аргументы или stdin внешней программы.
- **KWallet напрямую:** покрывает KDE, но Secret Service работает и там (KWallet предоставляет его), а отдельный бэкенд — лишний код.
- **Шифровать файл мастер-паролем на Linux:** работает без службы, но пароль нужно спрашивать при каждом запуске; владелец выбрал память как запасной вариант (ADR 0006).

## Последствия
- Проще: один `ISecretStore` для всех десктопных ОС, ключ не появляется в файлах, интерфейс страницы ключа знает, сохранится ли ключ.
- Сложнее: на Linux без gnome-keyring или KWallet ключ надо вводить после каждого запуска; на macOS и в части Windows-сценария проверка только по документации (статусы «не проверено» в задаче 040); в CI Secret Service не поднимается, интеграционный тест для Linux пропускается.
- Зависимости: `Tmds.DBus` (только Avalonia-оболочка), `System.Security.Cryptography.ProtectedData` (можно убрать, если Windows-сборка будет использовать только MAUI).
