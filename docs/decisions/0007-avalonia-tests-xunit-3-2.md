# 0007. Тесты Avalonia на xunit v3 3.2.2

Статус: принято
Допустимые статусы: предложено, принято, заменено на NNNN, отклонено
Дата: 2026-10-28

Дополняет ADR 0004 (xUnit v3) и ADR 0006 (Avalonia). Касается только `ImageGen.Avalonia.Tests`.

## Контекст
`Avalonia.Headless.XUnit` 12.1.4 (нужен для `[AvaloniaFact]`, см. ADR 0006 и задачу 039) собран против xunit v3 3.x. Центральный список `ImageGen/Directory.Packages.props` закрепляет `xunit.v3` 4.0.2. При обнаружении тестов падает `MissingMethodException` в `TestIntrospectionHelper.GetTestCaseDetails` (сигнатура кортежа изменилась в 4.x), тесты не запускаются. Остальные тестовые проекты (Core, Data, Presentation) на 4.0.2 работают, их трогать не нужно.

## Решение
В `ImageGen.Avalonia.Tests.csproj` пакет `xunit.v3` берётся с `VersionOverride="3.2.2"` (минимальная версия, которую требует `Avalonia.Headless.XUnit`). Остальные проекты остаются на версии из центрального списка. Тесты Avalonia проверены на этой комбинации: 4 из 4 проходят.

## Альтернативы
- Обновить `xunit.v3` до 3.2.2 во всём решении: одна версия, но меняет закреплённые версии у проектов, которые уже работают на 4.0.2.
- Не использовать `Avalonia.Headless.XUnit`, а поднимать headless-приложение вручную в тестовом фикстуре: без обхода версий, но больше своего кода и отход от документации Avalonia.
- Ждать версию `Avalonia.Headless.XUnit`, собранную под xunit v3 4.x: откладывает тесты интерфейса неизвестно на сколько.

## Последствия
- Проще: тесты интерфейса работают по документации Avalonia (`[AvaloniaFact]`, `AvaloniaTestApplication`).
- Сложнее: в решении две версии xunit v3. При обновлении `Avalonia.Headless.XUnit` или `xunit.v3` надо проверить, можно ли убрать `VersionOverride` и вернуть общую версию; после этого ADR помечается «заменено на NNNN» или отклонено.
