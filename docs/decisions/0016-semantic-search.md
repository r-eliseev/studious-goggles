# 0016. Поиск по смыслу: где считать векторы и где их хранить

Статус: предложено
Допустимые статусы: предложено, принято, заменено на NNNN, отклонено
Дата: 2026-10-29

## Контекст
Задача 079 даёт нечёткий поиск по словам: по названиям, промптам и описаниям картинок. Владелец хочет поиск по смыслу — по текстам и по самим картинкам («найди все картинки с маяком» без слова в промпте) (`tasks/backlog/081-semantic-search-research.md`). Принципы: BYOK (ключи провайдеров пользователя), приватность (промпты и картинки уходят только провайдерам, которых выбрал пользователь, F10.6), работа на Android и iOS, новые пакеты — только через ADR.

Сведения о моделях и ценах взяты 2026-10-29: каталог эмбеддингов OpenRouter (`https://openrouter.ai/api/v1/embeddings/models`, 38 моделей) и схема `POST /embeddings` из `https://openrouter.ai/openapi.json`; лицензии и файлы — карточки Hugging Face. Замеры скорости — `poc/backlog/081-semantic-search-research/` (README там же).

## Что уже известно

**API эмбеддингов OpenRouter** (`POST /embeddings`): `input` — строка, массив строк или массив объектов `{ "content": [ { "type": "text", "text": … } | { "type": "image_url", "image_url": { "url": … } } ] }`. Ответ: `data[].embedding` (массив чисел или base64), `usage.cost` (стоимость в кредитах; для эмбеддингов в схеме есть, точная единица не проверена вызовом). По схеме поле `session_id` не передаётся провайдеру (используется для журнала OpenRouter); назначение поля `user` в описании схемы не раскрыто.

**Замеры на облачном Linux-CPU** (4 логических CPU, не телефон): e5-small — 10 мс на текст из 32 токенов; многоязычный CLIP-текст — 13 мс; CLIP-визуальная часть — 37 мс на картинку 224×224. Перебор в памяти: 10 000 векторов по 512 — около 8 мс на запрос; 50 000 — 8–13 мс. Качество поиска не измерено (нет размеченного набора).

**Хранение**: `sqlite-vec` в NuGet — только alpha (`0.1.7-alpha.2`); в PyPI пакет есть. Для SQLite с BLOB и перебором в памяти измерения дают приемлемое время до 50 000 векторов по 512 измерений (около 100 МБ в памяти для float32).

## Решение (предложение)
1. **Текст** — вариант A: эмбеддинги текста через уже подключённый OpenRouter, модель `baai/bge-m3` (многоязычная, $0.01 за 1 млн токенов). Поиск по названиям, промптам и описаниям картинок, как 079, но по смыслу.
2. **Картинки** — отдельно, после согласия владельца на новый поток данных: вариант B с моделью, выбранной по цене и качеству (`google/gemini-embedding-2` или `voyageai/voyage-multimodal-3.5`; цена картинки нужно уточнить вызовом). До согласия — вариант D: поиск по описаниям картинок, который уже есть в 019.
3. **Хранение векторов**: SQLite, таблица с BLOB (float32 или float16), перебор в памяти при поиске. `sqlite-vec` — когда появится стабильная версия под .NET; сейчас он в alpha.
4. **Локальные модели (C)** — не в первых версиях: размер ≈ 860 МБ неприемлем для мобильной сборки. Вернуться после измерения качества на размеченном наборе и проверки ONNX Runtime на Android и iOS.
5. **Переиндексация** старых сессий и новых картинок — в фоне, как сводка (083): новые записи индексируются при сохранении, старые — по одной фоновой задаче при появлении ключа.

## Открытые вопросы владельцу
1. Разрешаете ли отправлять картинки провайдеру эмбеддингов (новый поток данных, отдельное согласие, как F10.6)? Если нет — поиск по картинкам идёт через описания (вариант D).
2. Текст: `baai/bge-m3` через OpenRouter ($0.01 за 1 млн токенов) или `openai/text-embedding-3-small` ($0.02, английский лучше протестирован — не проверено)?
3. Картинки: какой провайдер — gemini-embedding-2 или voyage-multimodal-3.5? Нужно ли уточнить цену картинки вызовом (нужен ключ владельца)?
4. Нужен ли офлайн-режим (тогда локальные модели, ≈860 МБ на десктопе)?
5. Переиндексация: сразу при первом включении поиска по смыслу или по мере работы в фоне?

## Последствия
- Текстовый поиск по смыслу не требует новых пакетов и моделей в сборке: только новый вызов `POST /embeddings` в клиенте OpenRouter (`ImageGen.Core/OpenRouter/`) и таблица векторов.
- Картинки через провайдера создают новый поток данных и новую статью расходов: без согласия не делаем.
- Качество не измерено ни для одного варианта: до реализации нужен PoC с размеченным набором (20 запросов на русском и английском, 50 картинок).
